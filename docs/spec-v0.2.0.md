## 転記する部分：言語仕様

### 組み込み型名

**[src.type-names]** 次の組み込み型名は予約されている。

```text
i8 i16 i32 i64 u8 u16 u32 u64 f32 f64 bool text void
```

### text

**[type.text]** `text` は、変更不能なUTF-8のバイト列を表す組み込み型である。空文字列も値として扱う。NULは内容の一部であり、終端ではない。長さは内容のバイト数である。

**[text.intern]** `text` は必ずインターン化する。同じ長さ・同じ全バイトの値は、生成方法や生成時点によらず、プログラム全体で同じ実体を共有する。異なるバイト列は異なる実体とする。Unicodeの正規化は行わない。

**[text.lifetime]** `text` の実体はプログラム終了まで有効である。変数のスコープを抜けたり、関数から戻ったり、変数へ別の値を再代入したりしても、以前の実体は解放しない。実体を保存する領域をテキストプールと呼ぶ。

**[text.copy]** `text` の代入、引数渡し、戻り値の受け渡しでは、実体を指す情報をコピーする。文字列全体の複製、再検索、新たな実体の保存は行わない。構造体のフィールドに格納できる。`var` の `text` には別の値を再代入でき、再代入は以前の実体を変更しない。型の一致と型推論には通常の値の規則を適用する。

**[text.compare]** `text` 同士の `==` と `!=` は、共有する実体の同一性で一致・不一致を判定する。結果は長さと全バイトの比較結果と一致し、判定は文字列の長さによらず定数時間とする。比較の連鎖には通常の比較の規則を適用する。

**[text.order]** `text` 同士の `<`、`<=`、`>`、`>=` は、Unicodeコードポイント列の辞書順で比較する。最初に異なるコードポイントの大小で順序を決める。片方がもう片方の接頭辞である場合は、短い方を先とする。同じ列は等しい。Unicodeの正規化は行わない。比較の連鎖には通常の比較の規則を適用する。

```suz
fix prefix_first = `a` < `aa`
fix codepoint_order = `A` < `a`
fix chain = `a` < `b` <= `b`
```

いずれも `true` となる。

**[text.operations]** `text` の二項演算には `==`、`!=`、`<`、`<=`、`>`、`>=` を使える。他の型との比較と算術演算はコンパイルエラーである。`as` による変換は [text.cast] に従う。`as%` による変換は [text.cast-wrap] に従う。連結はテンプレートへの埋め込みで表す。

```suz
fix left = `Hello`
fix right = `Suz`
fix joined = `${left}, ${right}!`
fix empty = joined == ``
```

### textからの型変換

**[text.cast]** `text` から整数型、浮動小数点型、`bool`、構造体型への `as` は、内容全体を変換先の型の値として読み取る。変換元は1回だけ評価する。文字列の内容を式として評価せず、数値・真偽値は [text.cast-format]、構造体は [text.cast-struct] の形式に従って解析する。それ以外の型への変換と、他の型から `text` への `as` はコンパイルエラーである。

**[text.cast-wrap]** `text` から整数型への `as%` は、内容全体を10進整数として読み、変換先のビット幅に収める。入力は [lit.integer] の整数リテラル、またはその直前に `-` を1つ付けた形とする。符号なし整数型への変換でも負数を受け付ける。変換元は1回だけ評価する。

入力の数学的な整数値を2^Nで割った非負の剰余を取り、Nビットの値とする。Nは変換先のビット数である。符号付き整数型では、そのビット列を2の補数として解釈する。整数値の大きさや桁数によって変換失敗とはしない。書式が不正な場合は変換失敗とする。浮動小数点型、`bool`、構造体型など、整数型以外への `as%` はコンパイルエラーである。

```suz
fix wrapped = `256` as% u8 or 0
fix negative = `-1` as% u8 or 0
fix signed = `255` as% i8 or 0
fix invalid = `1.0` as% u8 or 7
```

`wrapped` は0、`negative` は255、`signed` は−1、`invalid` は7となる。最初の3つは変換に成功し、代替値を評価しない。

**[text.cast-handler]** `text` からの `as` と `as%` には、`or 式` または `or return` を必ず付ける。定数式からの変換でも省略できない。[const.cast-check] による成功時の省略規則は適用しない。`as% 型` の直後の `or` も、その変換の失敗処理として結合する。代替値には変換先の型を要求し、変換が失敗した場合だけ評価する。`or return` の戻り値と記述位置、`expr` 系内部での脱出禁止、`or` の結合には [expr.cast-return]、[expr.or-return-position]、[expr.jump-prohibited]、[expr.cast-binding] を適用する。

```suz
fix count = `1_000` as u16 or 0
fix enabled = `true` as bool or false
fix rate = `1.5e-3` as f64 or 0.0
fix fallback = `256` as u8 or 0
```

`count` は1000、`enabled` は `true`、`rate` は0.0015を `f64` に丸めた値、`fallback` は0となる。

**[text.cast-format]** 変換先ごとの入力形式は次のとおりとする。数値の区切りの `_` はSuzのリテラルと同じ位置に書ける。大文字と小文字を区別する。

| 変換先 | 入力形式 |
|---|---|
| 符号付き整数型 | [lit.integer] の整数リテラル、またはその直前に `-` を1つ付けた形 |
| 符号なし整数型 | [lit.integer] の整数リテラル |
| `f32`・`f64` | [lit.integer] の整数リテラル、[lit.float] の浮動小数点リテラル、`nan`、`inf`、またはそれらの直前に `-` を1つ付けた形 |
| `bool` | `true` または `false` |

前後や途中の空白、NUL、コメント、括弧、演算など、上記の形式に含まれないバイトがある場合は変換失敗とする。空文字列も変換失敗とする。先頭の `+` は受け付けない。浮動小数点リテラルの指数部には [lit.float] に従って `+` を書ける。

| 入力と変換先 | 結果 |
|---|---|
| `-128` → `i8` | −128 |
| `128` → `i8` | 変換失敗 |
| `-1` → `u8` | 変換失敗 |
| `1` → `f64` | 1.0 |
| `1.0` → `u8` | 変換失敗 |
| `-inf` → `f64` | 負の無限大 |
| `nan` → `f32` | NaN |
| `false` → `bool` | false |
| `True` → `bool` | 変換失敗 |
| `1` → `bool` | 変換失敗 |

**[text.cast-range]** 整数型への変換は、符号を含めた正確な整数値が変換先の型の範囲内なら成功し、範囲外なら失敗する。浮動小数点型への変換は、正確な値から変換先の型へ直接、最近接・偶数丸めする。有限の入力を丸めた結果が無限大になる場合は失敗する。最大有限値、非正規化数、0に丸められる場合は成功する。負の数値が0に丸められた場合と `-0`・`-0.0` は負のゼロとする。`nan`・`inf` とその直前に `-` を付けた形は、同じ表記のSuzの値として扱う。

**[text.cast-struct]** 構造体型への変換は、`型名 { フィールド名: 値, ... }` の形式で内容全体を読む。型名は変換先の構造体型の名前と一致しなければならない。全フィールドを1回ずつ指定し、指定順は自由とする。型名の不一致、フィールドの欠落・重複・未知の名前、いずれかのフィールド値の読み取り失敗は、構造体全体の変換失敗とする。

```suz
struct Point {
    x: i32,
    y: i32,
}

fn main() -> u8 {
    fix point = `Point { y: 20, x: 10 }` as Point or Point { x: 0, y: 0 }
    log info `${point.x}, ${point.y}`
    return 0
}
```

変換は成功し、`point.x` は10、`point.y` は20となる。入力が `Point { x: 10 }` や `Point { x: 10, y: wrong }` の場合は、代替値の `Point { x: 0, y: 0 }` を使う。構造体への変換にも [text.cast-handler] を適用する。

**[text.cast-struct-field]** 各フィールドの値は、そのフィールドの型に従って読む。

| フィールド型 | 入力形式 |
|---|---|
| 整数型・浮動小数点型・`bool` | [text.cast-format] と [text.cast-range] に従う値 |
| `text` | バッククォートで囲んだ、埋め込みのない文字列 |
| 列挙型 | フィールドの列挙型名と列挙子名を `.` でつないだ形。宣言済みの列挙子に一致することを要求する |
| 構造体型 | [text.cast-struct] に従う入れ子の構造体リテラル |

値の位置に、変数名、定数名、関数呼び出し、算術式、型変換などを書いた入力は変換失敗とする。入れ子も値の表記として読み、Suzの式として実行しない。

**[text.cast-struct-text]** `text` フィールドの文字列には [text.escape] と [text.template-line] の形式を適用する。変換入力中の不正なエスケープや改行は、コンパイルエラーではなく変換失敗として扱い、`or` の処理へ進む。定数式からの変換でも同じとする。Suzのソース自体に書いたテンプレートの字句検査とは区別する。エスケープを展開した内容は、入力全体の検査後に [text.cast-struct-result] に従ってインターン化する。エスケープされていない `${` がある場合は変換失敗とする。文字として `${` を含める場合は `\${` と書く。バッククォートは `` \` ``、NULは `\0` で表す。

次は、変換元の `text` の内容である。

```text
Label { name: `Suz` }
```

同じ内容をSuzのソースに書く場合は、外側のテンプレートに含めるバッククォートをエスケープする。

```suz
struct Label {
    name: text,
}

fn main() -> u8 {
    fix input = `Label { name: \`Suz\` }`
    fix label = input as Label or Label { name: `` }
    log info `${label.name}`
    return 0
}
```

**[text.cast-struct-layout]** 構造体のトークン間にはSuzの空白と改行を使える。フィールドを区切るカンマと末尾カンマには [src.list-comma] と [src.trailing-comma] を適用する。要素と区切りのカンマの間には、文の区切りとなる改行を認めない。行数の判定は、変換元の `text` の内容に含まれる改行を使う。LFとCRLFを改行として扱い、単独のCRは変換失敗とする。

入力全体の先頭は型名、末尾は対応する `}` とする。前後の空白や余分な文字、文字列の外のコメントは変換失敗とする。数値の符号と値の間に空白を挟むことも変換失敗とする。

**[text.cast-struct-result]** 全フィールドと入力末尾までの検査が成功した場合だけ、構造体の値を結果として返す。形式や値の不正で変換に失敗した場合は、入力中の文字列を新たにテキストプールへ保存しない。全体の検査後、`text` フィールドの実体をインターン化して結果を作る。

解析用の一時領域、文字列の実体、検索用管理領域の確保失敗やプール上限超過は、変換失敗ではなく [rt.text-allocation] のパニックとする。`or` が処理するのは入力の形式と値の不正である。

**[const.text-cast]** 定数式の `text` からの `as` と `as%` は定数式として評価できる。`or` の代替値も定数式とし、実行時と同じ形式・範囲・丸め・ラップの規則で判定する。構造体への変換も対象とし、フィールドを再帰的に検査する。成功した結果の `text` フィールドはconstant textとして配置する。変換が失敗した場合は代替値を使う。成功する変換であっても [text.cast-handler] に従って `or` を必須とする。

```suz
const ENABLED = `true` as bool or false
const COUNT: u8 = `256` as u8 or 10
```

`ENABLED` は `true`、`COUNT` は10となる。

### テンプレート式

**[text.template]** バッククォートで囲むテンプレートを式として使うと、`text` 型の値を生成する。エスケープ、本文、埋め込み、1行の制約、値の表示は [text.escape]、[text.template-text]、[text.interpolation]、[text.template-line]、[text.value-format] に従う。空のテンプレートは空文字列を表す。ログ文に直接書くテンプレートは [log.temporary-text] に従う。

**[text.template-evaluation]** テンプレート中の式は左から右へ1回ずつ評価する。内容を組み立てた後、同じ内容の実体があれば再利用し、なければ新たに保存する。生成中にパニックした場合は値を返さない。

```suz
fn greeting(name: text) -> text {
    return `Hello, ${name}!`
}

fn main() -> u8 {
    var name: text = `Suz`
    fix first = greeting(name)
    name = `World`
    fix second = greeting(name)
    log info `${first}`
    log info `${second}`
    return 0
}
```

`first` の内容は `Hello, Suz!`、`second` の内容は `Hello, World!` となる。`greeting` が戻った後も `first` の実体は有効であり、`name` の再代入は `first` に影響しない。ログにはそれぞれの内容を埋め込む。

次の例では、直接書いたテンプレートと埋め込みによって生成した値が、同じ実体を共有する。

```suz
fix name = `Suz`
fix generated = `${name}`
fix same = name == generated
```

`same` は `true` となり、`generated` の生成によって `Suz` の実体が追加されることはない。型の一致、型推論、関数の引数と戻り値、構造体フィールドへの格納には、既存の値の規則を適用する。

### テンプレートの記法と値の表示

**[text.template-line]** テンプレートは、開くバッククォートから閉じるバッククォートまで、ソース上の1行に書く。内容に改行を含める場合は `\n` を使う。

**[text.template-text]** テンプレートの本文では、`//` は文字として扱う。`${` は埋め込みを開始する。文字として `${` を含める場合は `\${` と書く。埋め込み式の中は通常の式の字句規則に従う。

**[text.interpolation]** `${式}` は、式を評価した値の表示に置き換える。埋め込み式は左から右に、それぞれ1回評価する。埋め込める値の型は整数型、浮動小数点型、`bool`、列挙型、`text` である。それ以外の型を埋め込むとコンパイルエラーである。既存の `text` を埋め込んでも、その実体の保持期間は変わらない。

**[text.escape]** テンプレートの本文では、次のエスケープを使える。表にないエスケープはコンパイルエラーである。

| 記法 | 意味 |
|---|---|
| `\0` | U+0000を表す1バイトのNUL |
| `\n` | 改行 |
| `\r` | 復帰 |
| `\t` | タブ |
| `\\` | バックスラッシュ |
| `` \` `` | バッククォート |
| `\$` | `$` |

**[text.value-format]** 埋め込んだ値は、次の形式で表示する。

| 型 | 表示 |
|---|---|
| 整数 | 10 進数 |
| 浮動小数点 | 同じ型で読み戻すと同じ値になる最短表記。小数点を含める |
| `bool` | `true` または `false` |
| 列挙型 | 列挙子名。`Wave.Sine` なら `Sine` |
| `text` | 内容の全バイトをそのまま挿入する |

**[text.float-format]** 有限の浮動小数点値は、絶対値が 1e21 以上、または 0 より大きく 1e-6 未満の場合、`1.5e-8` のような指数表記にする。それ以外は通常の小数表記にする。どちらも小数点の両側に数字を置き、整数に見える値は `1.0` のように書く。NaN は `nan`、正の無限大は `inf`、負の無限大は `-inf`、負のゼロは `-0.0` と表示する。

**[text.nul]** インターン化、比較、埋め込み、ログ出力はNULを含む全バイトを扱う。

```suz
fix empty = ``
fix with_nul = `a\0b`
fix different = with_nul != `a`
log info `${with_nul}`
```

`empty` のバイト長は0、`with_nul` のバイト長は3、`different` は `true` となる。ログ本文は `a`、NUL、`b` の3バイトであり、ログの接頭辞と末尾のLFは既存の規則どおり付く。

### 定数式

**[const.expression]** 定数式は、数値・真偽値のリテラル、定数名、列挙子、定数式同士の演算と型変換、定数式から作る構造体リテラル、そのフィールド参照、丸括弧で囲んだ定数式から構成する。型変換と整数演算の `or` による代替値にも定数式を使える。埋め込みのないテンプレート、すべての埋め込みが定数式であるテンプレート、定数式の `text` 同士の比較も定数式である。

**[const.text]** 定数テンプレートは、実行時と同じエスケープと値の表示規則で評価する。数値リテラルの型は通常の型決定規則に従う。定数名を参照する規則を `fix` の値の参照には適用しない。ユーザー定義関数の呼び出しには [const.expression] の制約を適用する。

```suz
const PRODUCT: text = `Suz`
const MAJOR: u8 = 1
const LABEL = `${PRODUCT} ${MAJOR}`
```

`LABEL` の内容は `Suz 1` となる。定数の埋め込みも、実行時と同じエスケープと値の表示規則で評価する。数値の型が定まらない場合は、既存の数値リテラルの型決定規則を適用する。

### パターン照合

**[match.target]** `match` の対象は、整数、`bool`、列挙型、`text` の値である。それ以外の型を対象にするとコンパイルエラーである。対象は1回だけ評価し、一致した腕だけを実行する。

**[match.pattern]** パターンには、対象と同じ型の定数式を書く。定数式は [const.evaluation] に従って評価する。重複は評価した値で判定し、同じ値のパターンを重複して書くとコンパイルエラーである。`text` の重複はバイト列で判定する。整数と `text` の `match` では、残りすべてに一致する `_` を最後の腕に1回だけ書く。`bool` と列挙型の `match` に `_` を書くとコンパイルエラーである。

**[match.exhaustive]** `bool` の `match` は `true` と `false` の両方を、列挙型の `match` はすべての列挙子を、明示的に網羅しなければならない。整数と `text` の `match` は、必ず最後に `_` の腕を置く。この条件を満たさないものはコンパイルエラーである。

**[text.match]** `matchexpr` の対象にも `text` を使える。対象、パターン、重複、網羅性には [match.target]、[match.pattern]、[match.exhaustive] を適用する。分岐の結果型と脱出制御には通常の `matchexpr` の規則を適用する。

```suz
fn status_code(status: text) -> u8 {
    return matchexpr status {
        `ready` => 0
        `busy` => 1
        _ => 2
    }
}
```

### ログ

**[log.syntax]** ログは、`log info` のあとにテンプレートを1つ書く。テンプレートの記法、埋め込み、値の表示は [text.template-line]、[text.template-text]、[text.escape]、[text.interpolation]、[text.value-format]、[text.float-format] に従う。

**[log.evaluation]** すべての埋め込み式を評価して値を保持した後、そのログ文の出力を始める。評価中にパニックした場合、そのログ文の出力は始めない。

**[log.temporary-text]** ログ文に直接書いたテンプレートの本文は、一時的に組み立てて出力する。本文はインターン化せず、テキストプールにも登録しない。内容がコンパイル時に決まる場合も同じとする。埋め込み中の式が `text` を生成する場合は、その式に通常の生成と保持の規則を適用する。ログの出力形式と1回のログを一体として出力する規則は [log.output] とランタイム仕様に従う。

```suz
fix message = `Hello`
log info `${message}`
log info `count: ${1}`
```

`message` はインターン化された `text` である。2つのログの本文はtemporary textとして扱い、ログ出力そのものによってプールに文字列を追加しない。既存の `text` を埋め込んでも、その実体の保持期間は変わらない。

### text生成時のパニック

**[rt.text-allocation]** テキストプールの上限を超える追加確保が必要な場合、または文字列本体・検索用管理領域・一時領域を確保できない場合はパニックする。必要なバイト数が表現可能な範囲を超える場合も同じとする。計算をラップさせたり、途中までの文字列を成功した値として返したりしない。

**[rt.text-location]** 実行中の `text` 生成の失敗は、生成元のテンプレートの開くバッククォートの位置を示す。ログ本文の生成の失敗は、ログ文の `log` の位置を示す。`text` からの変換処理で資源不足が起きた場合は、その `as` または `as%` の位置を示す。プールの初期化の失敗は、`main` 宣言の `fn` の位置を示す。診断と終了コードは [rt.panic] に従う。

### EBNF

```ebnf
Type             ::= IntegerType | "f32" | "f64" | "bool" | "text" | "void" | IDENT
Primary          ::= Literal | IDENT | FunctionCall | StructLiteral | TEMPLATE
                   | "(" Expression ")" | IfExpression | MatchExpression | BlockExpression
Cast             ::= Unary ( "as%" Type CastHandler? | "as" Type CastHandler? )*
```

**[text.cast-wrap-handler-syntax]** `as%` の `CastHandler` は、変換元が `text` の場合に必須とする。変換元が整数型の場合に付けるとコンパイルエラーである。整数型から整数型への `as%` は [expr.as-trunc] に従う。

## 転記する部分：ランタイム仕様

### 責務と構成

**[runtime.layers]** 実行ファイルは、次の3つをリンクして構成する。

| 構成要素 | 責務 |
|---|---|
| 生成したC | Suzの処理、評価順序、分岐、ソース位置、constant textの本体と一覧、プール上限設定の保持、ランタイム本体の呼び出し |
| ランタイム本体 | 数値演算と変換の検査、値の表示、ログとパニック診断の組み立て、インターン化、文字列長の保持、プール容量の計測、一時領域の管理 |
| 環境層 | メモリの確保・解放、標準エラーへの出力、パニック時のプロセス終了 |

生成したCとランタイム本体は、メモリの確保・解放、出力、パニック終了を環境関数へ委譲する。環境層は渡されたバイト列の内容を変更せず出力する。演算の意味、値の表示、診断の内容、プール上限と確保失敗の検査はランタイム本体が決める。

### textの実体

**[runtime.text-storage]** 実装上、文字列本体を次のように区別する。

| 呼称 | 保存方法 |
|---|---|
| constant text | コンパイル時に内容が確定し、静的に配置する文字列本体 |
| dynamic text | 実行時にテキストプールへ確保する文字列本体 |
| temporary text | ログ出力用に一時生成し、出力後に解放または再利用する文字列本体 |

constant textとdynamic textは言語上の `text` の実体であり、同じインターン化の対象とする。temporary textはログ処理の内部だけで扱い、言語上の値として受け渡さない。

**[runtime.text-constant]** 言語仕様の定数式の規則で内容を確定できる `text` の式はconstant textとして配置する。最適化レベルによってこの分類を変えない。同じ内容は1つの実体にまとめる。ログ文に直接書いた本文は [log.temporary-text] に従い、共有実体として登録しない。埋め込み中にある `text` の式には定数式の規則を適用する。

**[runtime.text-intern]** 値を生成するときは、登録済みのconstant textとdynamic textの両方を検索する。同じ内容があれば既存の実体を再利用する。存在しない場合は、生成元がconstant textならその静的な本体を登録し、それ以外はdynamic textとして保存する。後から同じ内容のconstant textを使う場合も、登録済みの実体を再利用し、既存の値の同一性を変えない。ハッシュ値の一致だけで同じ内容と判定してはならない。衝突した値は内容を比較して区別する。

**[runtime.text-identity]** 実体を識別する方法にはアドレスや一意なIDなどを使える。保存領域を追加しても、既存の値が指す実体とその同一性は有効でなければならない。文字列本体を保持する領域はプログラム終了まで解放しない。

**[runtime.text-order]** 順序比較は文字列の内容を比較する。有効なUTF-8では、符号なしバイト列の辞書順とUnicodeコードポイント列の辞書順が一致するため、バイト単位で実装できる。最初の不一致または片方の末尾まで調べる。最悪時の比較時間は短い方のバイト長に比例する。同じ実体であれば、内容を走査せず等しいと判定してよい。

**[runtime.text-temporary]** 生成と検索のための一時領域は、実体の保存領域とは区別し、処理後に解放または再利用する。同じ内容の生成を繰り返すことで一時領域を保持し続けてはならない。temporary textの一時領域も出力後に解放または再利用する。

### 値の表示

**[runtime.value-format]** 値の表示は言語仕様の [text.value-format] と [text.float-format] に従う。整数・浮動小数点の表示は実行環境のロケールに依存させず、小数点には `.` を使う。`f32` の最短表記は `f32` として読み戻す条件で、`f64` は `f64` として読み戻す条件で決める。

### 初期化

**[runtime.text-init]** プールはSuzの `main` を呼び出す前に、上限設定を持つ空の状態で初期化する。constant textと空文字列は、実行時にその値が必要になった時点で登録する。定数の宣言や静的な本体の配置だけでは登録しない。呼ばれない関数や実行されない分岐にある文字列を、その存在だけを理由に登録してはならない。

初期化時に必要な動的管理領域も上限に数える。上限超過や確保失敗の場合は、初期化に失敗した理由を診断してパニックする。`main` 本体は実行しない。ソース位置は言語仕様の [rt.text-location] に従う。

### 容量と長さ

**[runtime.text-limit]** 保存領域は、生成プログラムに組み込まれた上限の範囲で必要に応じて追加確保する。上限相当の領域を起動時に一括確保する必要はない。無制限の設定でも、実行環境のメモリと長さの表現範囲には制約される。

**[runtime.text-accounting]** 上限は、プールが保持する文字列本体と検索用管理領域について、ランタイムが確保を要求したバイト数の合計に適用する。確保済み領域の未使用部分、保存用の終端バイト、アラインメント用の余白も数える。メモリアロケータ内部の管理費用、生成時の一時領域、プログラムの他のメモリは含めない。

constant textの本体は計測対象に含めない。dynamic textの本体と、constant textを検索するために動的確保した管理領域は数える。管理領域の拡張時に旧領域と新領域を同時に保持する場合は両方を数え、解放した要求サイズを差し引く。失敗した確保は計測値に加えない。

**[runtime.text-reuse]** インターン化では、既存の内容を探してから新しい実体や管理領域の追加確保を判断する。重複した値を取得するためだけに検索表を拡張して上限超過を起こしてはならない。プールが上限に達していても既存の実体を取得できる。ただし、内容の生成に必要な一時領域の確保は失敗しうる。

**[runtime.text-length]** 文字列長とプールの計測値はバイト単位の `u64` で扱う。文字列長には内容のバイト数だけを保持する。Cで確保・出力するときは、必要な長さが `size_t` で表現できることを検査する。加算と乗算はオーバーフローを検査してから結果を使う。空文字列のために0バイトの確保を要求する必要はない。

### 環境関数

**[runtime.env-interface]** `suz_env.h` は次の宣言を提供する。

```c
#ifndef SUZ_ENV_H
#define SUZ_ENV_H

#include <stddef.h>

void *suz_env_alloc(size_t size);
void suz_env_free(void *ptr);
void suz_env_log(const char *text, size_t len);
_Noreturn void suz_env_panic(void);

#endif
```

この4関数はCの呼び出し規約に従う。生成したCとランタイム本体が呼び出し側、環境層が実装側である。

**[runtime.env-alloc]** `suz_env_alloc(size)` は、要求サイズ以上を読み書きできる領域を返す。`size` は1以上とし、返す領域はCの `max_align_t` に適合するアラインメントを持つ。内容は未初期化とする。失敗時はNULLを返す。

**[runtime.env-free]** `suz_env_free(ptr)` は、同じ環境層の `suz_env_alloc` が返した未解放の領域を解放する。NULLは何もせず受け付ける。

**[runtime.env-memory]** 確保・解放の環境関数はSuzやランタイムへ再入しない。確保失敗による診断とパニックはランタイム側で行う。標準環境層は `malloc` と `free` で実装する。一時領域も同じ関数を使うが、プールの計測値には加えない。

### textからの型変換

**[runtime.text-parse]** `text` からの変換は、保持した長さで入力全体を読み、言語仕様の [text.cast-format]、[text.cast-range]、[text.cast-wrap]、[text.cast-struct] に従って判定する。NULを終端とした部分的な読み取りで成功させてはならない。ロケールによって、小数点・数字・空白・真偽値の解釈を変えない。

浮動小数点数は対象の型へ直接丸める。`f32` への変換で `f64` を経由することによる二重丸めを起こしてはならない。桁数や指数の大きな入力も、内部の整数計算をオーバーフローさせずに、値の範囲と丸めを判定する。

**[runtime.text-wrap-parse]** `as%` は、各桁を読みながら変換先のビット幅で剰余を保持するなど、入力全体を固定幅整数として保持せずにラップした値を求める。大きな整数を解析する際もCの未定義動作を起こしてはならない。剰余が既に決まっていても入力末尾まで書式を検査し、余分な文字や不正な区切りを成功として受け付けてはならない。

**[runtime.text-struct-parse]** 構造体の解析では、変換先の型と各フィールドの型に従い、名前、重複、欠落、値、入力末尾を検査する。入力全体の検査が成功するまで、新しい文字列の実体をプールへ保存しない。解析用の一時領域は成功・失敗のどちらでも解放または再利用する。入力の形式や値の不正は変換失敗として呼び出し側に返す。資源不足によるパニックには、変換元の `text` を生成した位置ではなく、変換する `as` のソース位置を使う。

### メモリ不足時の診断

**[runtime.text-panic]** 上限を超える確保要求は環境関数を呼ぶ前に検出する。診断は英語で、プール上限超過、メモリ確保失敗、文字列長の範囲超過を区別する。上限超過では、設定された上限、現在の計測値、追加確保に必要なバイト数を示す。

メモリ不足の診断は、プールへの登録や動的なメモリ確保を必要としない方法で組み立てる。`suz_env_log` と `suz_env_panic` を使い、診断位置は言語仕様の [rt.text-location] に従う。出力失敗時も [runtime.output-failure] と [runtime.env-panic] に従う。

## 転記する部分：ツール仕様

### テキストプールの上限

**[tool.text-pool-limit]** `--text-pool-limit SIZE` は、生成するプログラムのテキストプールの上限を指定する。`build`、`run`、`emit-c` で受け付ける。省略時は `1G` とする。設定は生成するプログラムに組み込む。`emit-c` では設定を生成物に含め、そのCから作った実行ファイルにも適用する。

| SIZE | 意味 |
|---|---|
| 正の10進整数 | バイト単位の上限 |
| 正の10進整数に `K`、`M`、`G` を付けた値 | それぞれ1,024、1,048,576、1,073,741,824倍のバイト数 |
| `unlimited` | 無制限 |

1Gは1 GiB、すなわち1,073,741,824バイトである。無制限はプール固有の容量制限を設けないという意味であり、実行環境のメモリや長さの表現範囲には制約される。計測対象はランタイム仕様の [runtime.text-accounting] に従う。

**[tool.text-pool-size]** 数値部分はASCIIの数字だけとし、単位は大文字で書く。0、負数、不正な表記、単位換算後の値が64ビット符号なし整数の範囲を超える指定、同じオプションの重複指定は使用方法のエラーとする。単位換算はオーバーフローを検査してから結果を使う。

```sh
suz build program.suz -o program --text-pool-limit 256M
suz run program.suz --text-pool-limit 2G
suz emit-c program.suz -o generated --text-pool-limit unlimited
```

### オプション表

| オプション | build | run | check | emit-c | 意味 |
|---|---|---|---|---|---|
| `--text-pool-limit SIZE` | 可 | 可 | | 可 | テキストプールの上限。既定は `1G` |
