# Suz v0.3.1 追加仕様

## 転記しない部分：編集要領

この文書は統合用の一時文書であり、v0.3.1では保持し、その次のバージョンへ移る際に削除する。仕様・例・検証条件は、以下の恒久的な反映先へ移す。

ログ本文を一時バッファへ組み立てる方式から、固定部分と埋め込み値を断片として出力する方式へ変更する。ログ本文の整形と出力のための動的メモリ確保をなくす。埋め込み式の評価順序、評価中のパニックによる出力抑止、ログ1件のアトミック性、出力バイト列は維持する。

constant textは、Suzのmainを呼ぶ前にすべて登録する。実行中の参照は登録済みの実体を直接使い、参照のたびのハッシュ計算・検索・登録をなくす。文字列本体は静的領域に置いたまま、dynamic textと同じインターン表で管理する。

「未使用のtextを登録しない」「初期化では登録しない」という既存の検証は、一括登録の検証へ置き換える。constant textより先にdynamic textを登録する実行順を前提とした検証も、初期化済みのconstant textとの共有を確認する内容へ変更する。初期化区間とmain実行中の区間を分けて計測し、ログ処理やconstant textの参照による確保と初期化コストを混同しない。

確保の検証は、生成したCとランタイム本体が行う要求を観測する。テスト用環境層の記録処理には静的領域または固定長の自動変数を使い、観測処理自身の確保を混ぜない。断片の具体的な分割位置や環境関数の呼び出し回数は固定せず、連結した出力とログ1件の排他範囲を検査する。

## 転記する部分：言語仕様

### ログの評価と出力

**[log.evaluation]** すべての埋め込み式を左から右へ1回ずつ評価し、値を保持した後、そのログ文の出力を始める。評価中にパニックした場合、そのログ文の出力は始めない。埋め込み式の中で実行したログは、その式の評価中に出力する。

**[log.fragments]** ログ文に直接書いたテンプレートは、固定部分と評価済みの埋め込み値を、本文の順に断片として出力する。ログ本文の整形と出力のために動的メモリを確保せず、本文をテキストプールへ登録しない。内容がコンパイル時に決まる場合も同じとする。埋め込むtextは、その実体に保持したバイト列を使う。埋め込み式自身がtextを生成する場合は、その式に通常の生成と保持の規則を適用する。出力形式は [log.output]、ログ1件のアトミック性はランタイム仕様に従う。

```suz
fix count: u8 = 3
log info `count: ${count}`
```

ログは `count: ` と数値の表示を本文の順に出力する。数値の整形には固定長の作業領域を使う。

```suz
fn make_text(count: u8) -> text {
    return `count: ${count}`
}
fn main() -> u8 {
    log info `${make_text(3)}`
    return 0
}
```

`make_text` が行うtextの生成と保持は、その関数の処理である。ログは戻されたtextのバイト列を出力し、出力用の本文を作るための追加確保を行わない。

### textの失敗位置

**[rt.text-location]** 実行中の `text` 生成の失敗は、生成元のテンプレートの開くバッククォートの位置を示す。`text` からの変換処理で資源不足が起きた場合は、その `as` または `as%` の位置を示す。埋め込み式の評価中も、失敗した生成・変換の位置を使う。プールの初期化の失敗は、`main` 宣言の `fn` の位置を示す。診断と終了コードは [rt.panic] に従う。

## 転記する部分：ランタイム仕様

### ログの断片出力

**[runtime.log-fragments]** ランタイム本体は、言語仕様の [log.output] と [log.fragments] に従って、接頭辞・本文の各断片・末尾の改行を `suz_env_log` へ順に渡す。分割位置と呼び出し回数によらず、連結した出力バイト列は同じでなければならない。

1つのログ文の接頭辞から末尾の改行までは、同じランタイムが出力する別のログやパニック診断を挟まず、ひとまとまりとして出力する。このアトミック性は、環境関数への受け渡しを複数回に分ける場合も、環境層が出力をバッファへ保留する場合も維持する。排他範囲は、すべての埋め込み式の評価が完了した後に開始し、末尾の改行を渡した後に終了する。

テンプレート内の `\n` も本文の一部として出力する。ログ文全体の末尾には、さらに改行を1つ付ける。本文の途中にある改行の後へ接頭辞を再挿入しない。textの出力には保持したバイト長を使い、NULを含む内容もそのまま渡す。出力失敗には [runtime.output-failure] を適用する。

**[runtime.log-storage]** 埋め込み値は生成したCの一時変数へ保持する。固定部分・名前・区切りは静的なバイト列を使い、数値の表示には型ごとに必要な容量を満たす固定長の自動変数を使う。textは保持済みのバイト列を環境関数へ渡す。ログ本文の整形と断片の受け渡しでは動的メモリの確保・解放を行わず、本文全体の長さに比例した作業領域を要求しない。埋め込み式自身の評価に必要な確保は、その式の規則に従う。

### textの実体と作業領域

**[runtime.text-storage]** 実装上、文字列本体を次のように区別する。

| 呼称 | 保存方法 |
|---|---|
| constant text | コンパイル時に内容が確定し、静的に配置する文字列本体 |
| dynamic text | 実行時にテキストプールへ確保する文字列本体 |

constant textとdynamic textは言語上の `text` の実体であり、同じインターン化の対象とする。

**[runtime.text-constant]** 言語仕様の定数式の規則で内容を確定できる `text` の式はconstant textとして配置する。最適化レベルによってこの分類を変えない。同じ内容は1つの実体にまとめ、[runtime.text-init] に従って起動時に登録する。文字列本体は静的領域に置き、そのバイト列を実体から参照する。ログ文に直接書いた本文は [log.fragments] に従って出力する。埋め込み中にある `text` の式には定数式の規則を適用する。

**[runtime.text-constant-access]** 実行中にconstant textの値を取得するときは、起動時に登録した実体を直接参照する。この取得ではハッシュ計算、インターン表の検索、登録、動的メモリ確保を行わず、文字列の長さによらず定数時間で処理する。

**[runtime.text-intern]** dynamic textを生成するときは、起動時に登録したconstant textと、登録済みのdynamic textの両方を検索する。同じ内容があれば既存の実体を再利用する。存在しない場合は新しいdynamic textとして保存する。既存の実体とその同一性を変更しない。ハッシュ値の一致だけで同じ内容と判定してはならない。衝突した値は内容を比較して区別する。

**[runtime.text-temporary]** textの生成と検索のための一時領域は、実体の保存領域とは区別し、処理後に解放または再利用する。同じ内容の生成を繰り返すことで一時領域を保持し続けてはならない。

### テキストプールの初期化

**[runtime.text-init]** テキストプールは、Suzの `main` を呼び出す前に上限設定を適用し、プログラム中のconstant textをすべて登録する。未使用の定数、呼ばれない関数、実行されない分岐に含まれるconstant textも対象とする。空文字列も、プログラム中にconstant textとして含まれる場合に登録する。同じ内容は1回だけ登録する。最適化レベルや到達可能性によって登録対象を変えない。ログ文に直接書いた本文とその固定部分はログの断片であり、それ自体はconstant textの登録対象に含めない。

登録時は静的な文字列本体をそのまま参照し、動的領域へコピーしない。静的な本体の保存バイト数はプール上限に数えず、動的に確保する登録用の管理領域は [runtime.text-accounting] に従って数える。

すべての登録が完了してからmainを呼び出す。上限超過や確保失敗の場合は、初期化に失敗した理由を診断してパニックする。main本体は実行しない。ソース位置は言語仕様の [rt.text-location] に従う。
