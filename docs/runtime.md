# Suz ランタイム仕様

この文書は、[言語仕様](spec.md)で定めた動作を、生成したC、ランタイム本体、環境層で実現するための契約を定める。規則名は言語仕様と同様に固定し、この文書では `runtime.` で始める。

## 1. 責務と構成

**[runtime.layers]** 実行ファイルは、次の3つをリンクして構成する。

| 構成要素 | 責務 |
|---|---|
| 生成したC | Suzの処理、評価順序、分岐、ソース位置、constant symbolの本体と一覧、プール上限設定の保持、ランタイム本体の呼び出し |
| ランタイム本体 | 数値演算と変換の検査、値の表示、ログとパニック診断の組み立て、インターン化、文字列長の保持、プール容量の計測、一時領域の管理 |
| 環境層 | メモリの確保・解放、標準エラーへの出力、パニック時のプロセス終了 |

生成したCとランタイム本体は、メモリの確保・解放、出力、パニック終了を環境関数へ委譲する。環境層は渡されたバイト列の内容を変更せず出力する。演算の意味、値の表示、診断の内容、プール上限と確保失敗の検査はランタイム本体が決める。

**[runtime.link]** 生成したCとランタイム本体は同じコンパイラ配布物のものを使う。環境関数の宣言は `suz_env.h` に置く。各環境関数の定義を実行ファイルに1つずつリンクする。標準環境層または本仕様を満たす環境層を選択する。

## 2. Cと実行環境の前提

**[runtime.c-target]** 生成したCとランタイムはC23を基準とし、[runtime.c-compiler] のコンパイラでビルドする。次の条件を満たす対象で動作する。

| 項目 | 条件 |
|---|---|
| バイト | `CHAR_BIT` が8 |
| 整数 | `<stdint.h>` の `int8_t` から `int64_t`、`uint8_t` から `uint64_t` が存在する |
| 浮動小数点 | Cの `float` がIEEE 754のbinary32、`double` がbinary64 |
| 浮動小数点の値 | 非正規化数、符号付きゼロ、無限大、NaNを言語仕様どおりに扱う |
| 浮動小数点の評価 | 各Suz演算の結果を、その式の型の精度で最近接・偶数丸めする |
| プロセス終了 | 0から255までの正常終了コードと、パニックの終了コード101を呼び出し元が観測できる |

コンパイラは、対象とCのビルド設定がこれらの条件を満たすことを確認する。満たせない対象や設定でのビルドはエラーにする。

**[runtime.c-compiler]** 生成したCとランタイムは、C23に対応したClangでビルドする。C23の言語機能、Clangが提供するヘッダー、Clangの拡張を使える。CライブラリのC23追加ヘッダーは、[tool.platform] のSDKが提供する場合に使える。Clangの最低バージョンは定めず、必要な機能を [runtime.c-check] で検査する。

**[runtime.c-extensions]** 生成Cとランタイム本体が使うClang拡張は、名前と用途を本規則に記載し、使用する変更と同時に更新する。共通の設定ヘッダーで `#pragma float_control(precise, on)` を使い、浮動小数点の演算順序や符号付きゼロなどを無視する最適化を抑える（[runtime.unsafe-math]）。FFIの関数型照合には `__typeof__` と `__builtin_types_compatible_p` を使う。C固有型の範囲検査にも128ビットの `_BitInt` を使う。同梱のRyuが使う拡張はRyuのREADMEで扱う。

**[runtime.c-check]** `suz_config.h` は `__clang__` の定義、`__STDC_VERSION__ >= 202311L`、128ビット以上の `_BitInt`、C23の `<stdckdint.h>` を要求する。条件を満たさない場合は必要な機能を英語の診断で示し、コンパイルエラーとする。Clang拡張を使用する場合は、プリプロセッサで検査できる機能を本ヘッダーで検査する。

**[runtime.integer-checked]** 算術式は、[arith.width] の推定範囲を表せる128ビット以下の `_BitInt` で正確に計算し、格納時に範囲を検査する。符号と絶対値を分けて保持してよい。64ビットの型に収まる部分は、その型で計算してよい。シフトの検査は [rt.shift-count] と [rt.shift-overflow] に従う。検査に失敗した場合、結果の出力先は変更しない。

**[runtime.arith-exact]** 整数の算術式は動的メモリを確保せずに計算する。128ビット以下の整数操作を使い、各演算に必要な手順数には入力値によらない上限を設ける。

**[runtime.compare-int-float]** 整数と浮動小数点数の比較では、整数を浮動小数点数へ丸めない。NaN・無限大・ゼロを先に処理し、負のゼロも整数の0と等しく扱う。有限の浮動小数点数を整数の仮数と2のべき乗に分解し、整数と正確に比較する。内部では大小関係を「小さい」「等しい」「大きい」「比較不能」の4種類で表す。比較不能の場合は `!=` だけを真とする。128ビット以下の整数操作と入力値によらない上限のある手順で処理し、動的メモリを確保しない。同じ結果になることを型の範囲から証明できる場合は、通常の比較を使ってよい。

**[runtime.float-environment]** ランタイム本体はSuzの処理を始める前に、浮動小数点の丸めを最近接・偶数丸めとし、浮動小数点例外を値の結果として扱う実行環境を整える。生成したCとランタイムは、最近接・偶数丸めと、浮動小数点例外をトラップしない環境を前提にコンパイルする。環境を初期化する `suz_runtime_init` の本体だけを `#pragma STDC FENV_ACCESS ON` の範囲に置き、それ以外の生成Cとランタイムには適用しない。環境関数は、この設定を変更してはならない。

生成したCのコンパイルでは、演算の再結合、積和への縮約、非正規化数のゼロへの置換などによってSuzの結果が変わる最適化を行わない。Cの式の途中だけ余分な精度が保持されることによって結果が変わる場合も、Suzの型の精度へ丸める処理を入れる。

**[runtime.unsafe-math]** 共通の設定ヘッダーで `#pragma float_control(precise, on)` と `#pragma STDC FP_CONTRACT OFF` を指定する。生成Cとランタイムのコンパイルでは、[tool.build-settings](tool.md) に従い `-fhonor-nans`、`-fhonor-infinities`、`-ffp-contract=off`、`-fdenormal-fp-math=ieee` を指定する。これらの固定フラグは追加フラグより後に置く。

この設定では、`-fno-signed-zeros`、`-freciprocal-math`、`-funsafe-math-optimizations`、`-fno-honor-nans`、`-fno-honor-infinities`、`-ffp-model=fast`、`-ffast-math`、`-ffinite-math-only` が固定フラグより前に指定されても、NaN・無限大・符号付きゼロを無視した最適化、逆数乗算への置換、演算の再結合・積和への縮約でSuzの結果を変えてはならない。

共通ヘッダーは、`__FAST_MATH__` が定義されている場合、または `__FINITE_MATH_ONLY__` が正の場合にコンパイルエラーにする。この検査は、フラグの指定履歴ではなく、最終的なマクロの状態を検査する。後続の固定フラグでこれらのマクロが無効になった場合は、この検査では拒否しない。Clangがフラグの上書きに警告を出した場合は、通常の `-Werror` によりビルドが失敗することがある。`SUZ_CFLAGS` では、これらの危険なフラグを許可リストで拒否する。

Clangの `contract=fast` はpragmaだけでは縮約を防げないため、固定フラグの `-ffp-contract=off` は必須である。また、NaN・無限大を無視する個別のフラグはマクロで検出できず、`float_control(precise, on)` だけでも打ち消せない。生成Cを手でコンパイルする場合も、これら4つの固定フラグを他の数値関連フラグより後に指定しなければならない。ヘッダーを読み込むだけで、任意のコンパイル設定に対して結果を保証するものではない。

## 3. 起動と正常終了

**[runtime.entry]** Cの入口関数は、ランタイム本体の実行環境を整えた後、Suzの `fn main() -> u8` を1回呼び出す。生成したCでは、Suzの関数名をCの入口関数名と区別する。

**[runtime.normal-exit]** Suzの `main` が返した値を、Cの `int` に変換してCの入口関数から返す。この値がプロセスの終了コードになる。たとえば、Suzの `main` が7を返した場合は終了コード7になる。

正常終了時には、環境層が保留した出力のフラッシュを試みてからプロセスを終了する。独自のバッファを持つ環境層は、`atexit` などで終了時のフラッシュ処理を登録する。フラッシュに失敗した場合も、Suzの `main` が返した終了コードで終了する。

## 4. 環境関数

**[runtime.env-interface]** `suz_env.h` は次の宣言を提供する。

```c
#ifndef SUZ_ENV_H
#define SUZ_ENV_H

#include "suz_config.h"
#include <stddef.h>

typedef enum {
    SUZ_LOG_INFO,
    SUZ_LOG_WARN,
    SUZ_LOG_PANIC,
    SUZ_LOG_DEBUG,
    SUZ_LOG_ERROR,
    SUZ_LOG_IGNORE,
} suz_log_level;

void *suz_env_alloc(size_t size);
void suz_env_free(void *ptr);
void suz_env_log(suz_log_level level, const char *text, size_t len);
_Noreturn void suz_env_panic(void);

#endif
```

この4関数はCの呼び出し規約に従う。生成したCとランタイム本体が呼び出し側、環境層が実装側である。

### 4.1 出力

**[runtime.env-log]** `suz_env_log(level, text, len)` は、`text` から始まる `len` バイトを標準エラーへ出力する。通常のログ・ignoreの記録・パニックの診断に使う。`level` は、`log debug` では `SUZ_LOG_DEBUG`、`log error` では `SUZ_LOG_ERROR`、`log info` では `SUZ_LOG_INFO`、`log warn` では `SUZ_LOG_WARN`、ignoreの記録では `SUZ_LOG_IGNORE`、パニックの診断では `SUZ_LOG_PANIC` とする。同じ出力の接頭辞・本文・末尾の改行には、すべて同じレベルを渡す。標準環境層はレベルを無視して出力する。`SUZ_LOG_IGNORE`と`SUZ_LOG_PANIC`は通常ログの重要度の序列には含めない。

| 項目 | 契約 |
|---|---|
| 入力 | `len` は1以上。引数 `text` は少なくとも `len` バイトを読み取れる領域を指す |
| 文字コード | 各呼び出しのバイト列は有効なUTF-8。断片の境界はUTF-8の文字境界とする |
| 終端 | 長さで範囲を指定する。NUL終端を前提にしない |
| 所有権 | 呼び出し側が所有する。環境関数は内容を書き換えない |
| 有効期間 | 呼び出しが戻るまで有効。環境関数はポインタを保存しない |
| 呼び出し単位 | 整形済みの出力断片。1回の呼び出しが1つのログ文や1行に対応するとは限らない |
| 順序 | 呼び出し順に連結したバイト列を出力する |
| 装飾 | 接頭辞、改行などの追加はランタイム本体が行う。環境関数は入力どおりに出力する |
| 完了 | 関数が戻るまでに、入力を出力するか環境層のバッファへコピーする。出力は呼び出し順を保つ |
| 再入 | 環境関数の実行中にSuzの処理やランタイムのログ・パニック処理を呼び出さない |

**[runtime.output-failure]** 出力が一部しか書き込まれなかった場合、環境層は残りの書き込みを試みる。一時的な中断で再試行できる場合は再試行する。継続できない書き込みエラーでは、その呼び出しの残りを破棄して戻る。パイプ切断なども出力失敗として扱う。

出力失敗による追加の診断やパニックは発生させず、Suzの処理を続ける。後続の環境関数の呼び出しでは、再び出力を試みる。パニック診断の出力に失敗した場合も、パニックの終了処理へ進む。

出力をバッファへ保留した場合も、実際に書き込むときにはこの規則に従う。

### 4.2 パニック終了

**[runtime.env-panic]** `suz_env_panic()` は、プロセス全体を終了コード101で終了させる。呼び出し元には戻らない。

環境層が保留した出力のフラッシュを試みてから終了する。フラッシュに失敗した場合も、終了コード101で終了する。

呼び出し前に、ランタイム本体がパニックの診断を `suz_env_log` に渡す。環境関数は終了処理を担当し、診断の組み立てはランタイム本体が担当する。

### 4.3 メモリの確保と解放

**[runtime.env-alloc]** `suz_env_alloc(size)` は、要求サイズ以上を読み書きできる領域を返す。`size` は1以上とし、返す領域はCの `max_align_t` に適合するアラインメントを持つ。内容は未初期化とする。失敗時はNULLを返す。

**[runtime.env-free]** `suz_env_free(ptr)` は、同じ環境層の `suz_env_alloc` が返した未解放の領域を解放する。NULLは何もせず受け付ける。

**[runtime.env-memory]** 確保・解放の環境関数はSuzやランタイムへ再入しない。確保失敗による診断とパニックはランタイム側で行う。標準環境層は `malloc` と `free` で実装する。一時領域も同じ関数を使うが、プールの計測値には加えない。

## 5. ログの評価と出力

**[runtime.log-evaluation]** [log.filter]で生成対象となった1つの `log debug`・`log info`・`log warn`・`log error` では、最初にすべての埋め込み式を左から右に1回ずつ評価し、それぞれの値を保持する。すべての評価が成功してから、そのログ文の出力を始める。

埋め込みには言語仕様の [output.embed-value] を適用し、名前とそのフィールド参照から値を読む。計算が必要な場合はログ文の前で行う。

**[runtime.log-fragments]** `suz_log_begin(level, source, line)` は `suz_log_level` の `SUZ_LOG_DEBUG`・`SUZ_LOG_INFO`・`SUZ_LOG_WARN`・`SUZ_LOG_ERROR`・`SUZ_LOG_IGNORE` を受け取り、出力のロックを取得して接頭辞を書く。`suz_log_end()` は改行を出力してロックを解放する。ランタイム本体は、言語仕様の [log.output] と [log.fragments] に従って、接頭辞・本文の各断片・末尾の改行を `suz_env_log` へ順に渡す。分割位置と呼び出し回数によらず、連結した出力バイト列は同じでなければならない。

1つのログ文の接頭辞から末尾の改行までは、同じランタイムが出力する別のログやパニック診断を挟まず、ひとまとまりとして出力する。このアトミック性は、環境関数への受け渡しを複数回に分ける場合も、環境層が出力をバッファへ保留する場合も維持する。排他範囲は、すべての埋め込み式の評価が完了した後に開始し、末尾の改行を渡した後に終了する。

テンプレート内の `\n` も本文の一部として出力する。ログ文全体の末尾には、さらに改行を1つ付ける。本文の途中にある改行の後へ接頭辞を再挿入しない。symbolの出力には保持したバイト長を使い、NULを含む内容もそのまま渡す。出力失敗には [runtime.output-failure] を適用する。

**[runtime.panic-fragments]** `suz_panic_begin(source, line, column)` は出力ロックを取得し、`SUZ_LOG_PANIC`で位置の接頭辞を出力する。続く本文は評価済みの値を`suz_log_*`の断片出力関数へ渡す。`suz_panic_end()`は改行を出力し、ロックを保持したまま`suz_env_panic()`で終了する。既存の`suz_panic`もこの開始・終了処理を使う。埋め込み式の評価はロック取得前に完了させる。本文の整形・出力は[runtime.log-storage]と同じく動的確保を行わない。

**[runtime.value-format]** 値の表示は言語仕様の [symbol.value-format] と [symbol.float-format] に従う。整数・浮動小数点の表示は実行環境のロケールに依存させず、小数点には `.` を使う。`f32` の最短表記は `f32` として読み戻す条件で、`f64` は `f64` として読み戻す条件で決める。

**[runtime.log-storage]** 埋め込み値は生成したCの一時変数へ保持する。固定部分・名前・区切りは静的なバイト列を使い、数値の表示には型ごとに必要な容量を満たす固定長の自動変数を使う。symbolは保持済みのバイト列を環境関数へ渡す。ログ本文の整形と断片の受け渡しでは動的メモリの確保・解放を行わず、本文全体の長さに比例した作業領域を要求しない。

## 6. 数値演算と変換

**[runtime.checked-operation]** ランタイム本体は、失敗しうる整数演算と型変換について、成功・失敗と、成功した場合の値を生成したCへ返せる処理を用意する。失敗時の値は使わない。

生成したCは、その結果から言語仕様の処理を選ぶ。

| 結果と失敗処理 | 動作 |
|---|---|
| 成功 | 計算した値を使う |
| 失敗し、`or 式` がある | 代替値の式を評価する |
| 失敗し、`or return` がある | 指定した戻り値を評価して関数から戻る |
| 整数演算に失敗し、対応する `or` がない | ソース位置と理由を使ってパニックする |

算術式の格納、ゼロ除算、シフトの検査条件と数値型・列挙型の変換の成功条件は、言語仕様の [rt.int-overflow] から [rt.as-int-enum] に従う。symbolからの変換は [runtime.symbol-parse]、[runtime.symbol-wrap-parse]、[runtime.symbol-struct-parse] に従う。

**[runtime.defined-c]** 検査は、Cの未定義動作が発生する前に行う。特に、符号付き整数のオーバーフロー、整数のゼロ除算、符号付き整数の最小値と-1の除算・剰余、不正なシフト数、範囲外の浮動小数点から整数への変換を、Cの演算を実行してから判定してはならない。

ラップ演算、`as%`、符号付き整数の右シフトも、言語仕様の結果を実現する。Cの整数拡張、符号付き型への範囲外変換、負数のシフトなどの扱いによってSuzの結果が変わらないようにする。

**[runtime.evaluation-order]** 生成したCは、Suzのオペランド・実引数・埋め込み式の評価順序を一時変数と文の順序で保持する。比較の連鎖では中間の値を再利用し、短絡評価では必要な部分だけを実行する。Cの実引数の評価順序にSuzの実行順序を委ねない。

## 7. パニックの診断

**[runtime.panic-sequence]** ランタイム本体は、最初にパニックした演算のソース位置と理由を診断として組み立て、`suz_env_log` へ順に渡す。診断の最後に改行を付け、その後 `suz_env_panic` を1回呼び出す。

診断はファイル名、行番号、列番号、失敗理由を識別できる形式とする。具体的な診断文言は固定せず、言語仕様の [rt.panic] に従う。

**[runtime.source-position]** ファイル名はコンパイラの診断に用いるソース名と共通にする。行と列は1から数え、CRLFをLFへ正規化したソースで位置を求める。列は行頭からのUnicodeスカラー値の個数に1を足した値とし、タブも1つとして数える。

算術式のパニック位置は [arith.location] に従う。シフトの失敗にはシフト演算子の位置を使う。複合代入自身の除算・剰余・格納・シフトの失敗には、複合代入演算子の位置を使う。生成したCの位置ではなく、Suzソースの位置を保持して渡す。

**[runtime.stack-exhaustion]** スタックを使い切ったときの異常終了は言語仕様の [rt.stack] に従う。診断の出力と終了コード101を保証するのは、[runtime.panic-sequence] に従って処理できた言語上のパニックである。

## 8. 実装の検証

**[runtime.verification]** 実装では、次を確認する。

| 対象 | 確認する結果 |
|---|---|
| 環境関数のリンク | `suz_env.h` の宣言と実装の型が一致し、各関数が1つずつ解決される |
| 正常終了 | Suzのmainの戻り値とプロセスの終了コードが一致する |
| charと文字の反復 | 定数評価と実行時の変換結果が一致し、サロゲート領域と整数境界を正しく扱う。symbolの前後の反復とcharのログ出力では、動的メモリを確保しない |
| 通常のログ | 全呼び出しの出力を連結すると言語仕様のバイト列になる |
| ログのアトミック性 | 断片への分割やバッファへの保留によらず、1つのログ文の接頭辞から末尾の改行までに、同じランタイムの別のログやパニック診断が混ざらない |
| 出力断片 | ログまたはパニックに対応するレベルを持ち、UTF-8として有効で、長さどおりに扱い、呼び出し終了後に入力ポインタを使用しない |
| 出力の保留 | 入力をコピーして呼び出し順を保ち、正常終了時とパニック終了時にフラッシュを試みる。失敗しても指定の終了コードで終了する |
| 埋め込み中のログ | 内側のログを完了してから外側のログを出力する |
| 埋め込み中のパニック | 外側のログを出力せず、診断の出力後に101で終了する |
| 出力失敗 | 一部書き込み、一時的中断、継続不能のエラーを環境関数の契約どおり処理する |
| パニック | 演算子のソース位置と理由を出力し、終了コード101になる |
| 数値処理 | 境界値、丸め、NaN、無限大、負のゼロ、非正規化数で言語仕様の結果になる |
| テキストの共有 | 起動時に登録したconstant symbolとdynamic symbolが同じ内容を共有し、ハッシュ衝突では異なる内容を区別する |
| constant symbolの参照 | 未使用の内容もmainの前に登録し、実行中の参照ではハッシュ計算・検索・確保を行わない |
| ログの作業領域 | 本文の整形と出力のために動的確保を行わない |
| プール容量 | 静的な本文を除き、管理領域・動的な本文・拡張中の旧領域と新領域を要求サイズで数える。既存の値は上限到達後も再利用できる |
| 一時領域 | symbolの生成や変換の成功・失敗の後に解放または再利用し、失敗した構造体変換でフィールドのsymbolを登録しない |
| symbolからの変換 | 入力全体の形式・範囲・直接丸め・ラップを検査し、失敗処理と資源不足のパニックを区別する |
| 確保失敗 | 上限超過を確保前に検出し、診断のために追加確保せず、生成・変換元の位置でパニックする |
| 最適化 | 最適化の有無でSuzの観測結果が変わらない |

環境関数への入力の記録と出力失敗の注入は、検証用の環境実装で行う。プロセスの終了コードは子プロセスを実行して確認する。ソース単位の動作は[仕様例集](spec-cases.md)と照合する。

## 9. テキストプール

### 9.1 実体と共有

**[runtime.symbol-storage]** 実装上、文字列本体を次のように区別する。

| 呼称 | 保存方法 |
|---|---|
| constant symbol | コンパイル時に内容が確定し、静的に配置する文字列本体 |
| dynamic symbol | 実行時にテキストプールへ確保する文字列本体 |

constant symbolとdynamic symbolは言語上の `symbol` の実体であり、同じインターン化の対象とする。

**[runtime.symbol-constant]** 言語仕様の定数式の規則で内容を確定できる `symbol` の式はconstant symbolとして配置する。最適化レベルによってこの分類を変えない。同じ内容は1つの実体にまとめ、[runtime.symbol-init] に従って起動時に登録する。文字列本体は静的領域に置き、そのバイト列を実体から参照する。ログ文に直接書いた本文は [log.fragments] に従って出力する。埋め込み中にある `symbol` の式には定数式の規則を適用する。

**[runtime.symbol-constant-access]** 実行中にconstant symbolの値を取得するときは、起動時に登録した実体を直接参照する。この取得ではハッシュ計算、インターン表の検索、登録、動的メモリ確保を行わず、文字列の長さによらず定数時間で処理する。

**[runtime.symbol-intern]** dynamic symbolを生成するときは、起動時に登録したconstant symbolと、登録済みのdynamic symbolの両方を検索する。同じ内容があれば既存の実体を再利用する。存在しない場合は新しいdynamic symbolとして保存する。既存の実体とその同一性を変更しない。ハッシュ値の一致だけで同じ内容と判定してはならない。衝突した値は内容を比較して区別する。

**[runtime.symbol-identity]** 実体はポインタで識別し、`symbol` 同士の等価比較とパターン照合ではポインタだけを比較する。保存領域を追加しても、既存の値が指す実体とその同一性は有効でなければならない。文字列本体を保持する領域はプログラム終了まで解放しない。

**[runtime.symbol-order]** 順序比較は文字列の内容を比較する。有効なUTF-8では、符号なしバイト列の辞書順とUnicodeコードポイント列の辞書順が一致するため、バイト単位で実装できる。最初の不一致または片方の末尾まで調べる。最悪時の比較時間は短い方のバイト長に比例する。同じ実体であれば、内容を走査せず等しいと判定してよい。

**[runtime.symbol-temporary]** symbolの生成と検索のための一時領域は、実体の保存領域とは区別し、処理後に解放または再利用する。同じ内容の生成を繰り返すことで一時領域を保持し続けてはならない。

### 9.2 初期化

**[runtime.symbol-init]** テキストプールは、Suzの `main` を呼び出す前に上限設定を適用し、プログラム中のconstant symbolをすべて登録する。未使用の定数、呼ばれない関数、実行されない分岐に含まれるconstant symbolも対象とする。空文字列も、プログラム中にconstant symbolとして含まれる場合に登録する。同じ内容は1回だけ登録する。最適化レベルや到達可能性によって登録対象を変えない。ログ文に直接書いた本文とその固定部分はログの断片であり、それ自体はconstant symbolの登録対象に含めない。

登録時は静的な文字列本体をそのまま参照し、動的領域へコピーしない。静的な本体の保存バイト数はプール上限に数えず、動的に確保する登録用の管理領域は [runtime.symbol-accounting] に従って数える。

すべての登録が完了してからmainを呼び出す。上限超過や確保失敗の場合は、初期化に失敗した理由を診断してパニックする。main本体は実行しない。ソース位置は言語仕様の [rt.symbol-location] に従う。

### 9.3 容量と長さ

**[runtime.symbol-limit]** 保存領域は、生成プログラムに組み込まれた上限の範囲で必要に応じて追加確保する。上限相当の領域を起動時に一括確保する必要はない。無制限の設定でも、実行環境のメモリと長さの表現範囲には制約される。

**[runtime.symbol-accounting]** 上限は、プールが保持する文字列本体と検索用管理領域について、ランタイムが確保を要求したバイト数の合計に適用する。確保済み領域の未使用部分、保存用の終端バイト、アラインメント用の余白も数える。メモリアロケータ内部の管理費用、生成時の一時領域、プログラムの他のメモリは含めない。

constant symbolの本体は計測対象に含めない。dynamic symbolの本体と、constant symbolを検索するために動的確保した管理領域は数える。管理領域の拡張時に旧領域と新領域を同時に保持する場合は両方を数え、解放した要求サイズを差し引く。失敗した確保は計測値に加えない。

**[runtime.symbol-reuse]** インターン化では、既存の内容を探してから新しい実体や管理領域の追加確保を判断する。重複した値を取得するためだけに検索表を拡張して上限超過を起こしてはならない。プールが上限に達していても既存の実体を取得できる。ただし、内容の生成に必要な一時領域の確保は失敗しうる。

**[runtime.symbol-length]** 文字列長とプールの計測値はバイト単位の `u64` で扱う。文字列長には内容のバイト数だけを保持する。Cで確保・出力するときは、必要な長さが `size_t` で表現できることを検査する。加算と乗算はオーバーフローを検査してから結果を使う。空文字列のために0バイトの確保を要求する必要はない。

### 9.4 メモリ不足時の診断

**[runtime.symbol-panic]** 上限を超える確保要求は環境関数を呼ぶ前に検出する。診断は英語で、プール上限超過、メモリ確保失敗、文字列長の範囲超過を区別する。上限超過では、設定された上限、現在の計測値、追加確保に必要なバイト数を示す。

メモリ不足の診断は、プールへの登録や動的なメモリ確保を必要としない方法で組み立てる。`suz_env_log` と `suz_env_panic` を使い、診断位置は言語仕様の [rt.symbol-location] に従う。出力失敗時も [runtime.output-failure] と [runtime.env-panic] に従う。


### 9.5 symbolからの型変換

**[runtime.symbol-parse]** `symbol` からの変換は、保持した長さで入力全体を読み、言語仕様の [symbol.cast-format]、[symbol.cast-range]、[symbol.cast-wrap]、[symbol.cast-struct] に従って判定する。NULを終端とした部分的な読み取りで成功させてはならない。ロケールによって、小数点・数字・空白・真偽値の解釈を変えない。

浮動小数点数は対象の型へ直接丸める。`f32` への変換で `f64` を経由することによる二重丸めを起こしてはならない。桁数や指数の大きな入力も、内部の整数計算をオーバーフローさせずに、値の範囲と丸めを判定する。

**[runtime.symbol-wrap-parse]** `as%` は、各桁を読みながら変換先のビット幅で剰余を保持するなど、入力全体を固定幅整数として保持せずにラップした値を求める。大きな整数を解析する際もCの未定義動作を起こしてはならない。剰余が既に決まっていても入力末尾まで書式を検査し、余分な文字や不正な区切りを成功として受け付けてはならない。

**[runtime.symbol-struct-parse]** 構造体の解析では、変換先の型と各フィールドの型に従い、名前、重複、欠落、値、入力末尾を検査する。入力全体の検査が成功するまで、新しい文字列の実体をプールへ保存しない。解析用の一時領域は成功・失敗のどちらでも解放または再利用する。入力の形式や値の不正は変換失敗として呼び出し側に返す。資源不足によるパニックには、変換元の `symbol` を生成した位置ではなく、変換する `as` のソース位置を使う。

## 10. charと文字の反復

**[runtime.char]** `char` は32ビット符号なし整数で保持し、値は常に言語仕様の [char.type] の範囲にある。文字リテラルと構造体入力の文字フィールドは同じ解析処理を使う。整数からの変換では負数、サロゲート領域、U+10FFFFを超える値を拒否する。

**[runtime.char-iteration]** `symbol` の反復は実体全体を、`text` の反復は指す範囲をUTF-8として復号する。逆順では継続バイトをたどって直前のスカラー値の先頭を見つけ、その値を復号する。NULを含む全バイトを対象にし、一時文字列や反復対象全体のコピーを作らない。反復・復号・ログへの `char` 出力は動的メモリを確保せず、テキストプールを使わない。文字範囲の反復も動的メモリを確保しない。


## 11. textの参照範囲

**[runtime.text-view]** `text` は、範囲の先頭バイトへのポインタ、バイト数、Unicodeスカラー値の個数を保持する。本文はプログラム終了まで有効な領域を参照し、コピーしない。`symbol` はインターン済みの実体を指し、実体に本文と両方の長さを保持する。

**[rt.len-type-representation]** `len_t` は生成Cの `int32_t` で表し、値は常に0以上2^31−1以下とする。

**[rt.len-limit]** `symbol` の登録時に数えるUnicodeスカラー値が2^31−1個を超える場合は、[rt.symbol-allocation] の長さ超過としてパニックする。検査のための追加走査は行わない。定数の `symbol` はコンパイル時に検査する。上限は個数に対するものであり、バイト数とバイトオフセットの表現範囲は縮めない。

**[rt.len-text]** `len` は `symbol` の実体または `text` の値に保持された個数を読む。`len` のための追加領域は持たない。

**[runtime.text-count]** `symbol` のスカラー値の個数は登録時までに求め、以後は保存した値を使う。`symbol` から `text` への変換と `[:]` では再走査しない。部分範囲の個数は終了位置と開始位置の差である。

**[runtime.text-position]** 切り出しと添字による読み取りでは、UTF-8のスカラー境界を先頭からたどって位置を求める。バイト数とスカラー値の個数が等しい範囲では、位置がバイトのオフセットと一致するため定数時間で求める。それ以外では、時間は走査する位置に比例する。両端の大小、負数、範囲外を検査し、不正なポインタ演算や符号なし整数への変換で負数を有効な位置にしてはならない。メモリを確保せず、プールの計測値を増やさない。

**[runtime.text-equality]** `text` の等値比較は、バイト長が異なれば不一致とする。同じ長さで空の範囲、または同じ先頭を指す範囲は、本文を読まず一致とする。それ以外では範囲内のバイト列を比較する。

**[runtime.text-operations]** 反復、比較、解析、出力は範囲内のバイトだけを読む。NULを終端として扱わない。構造体への変換で `text` フィールドを作る際は [runtime.symbol-struct-parse] の検査と保存を行う。

切り出し・読み取り・暗黙変換・比較・反復・変換と定数評価は仕様例集で検証する。確保の禁止、範囲外のアクセス、インターン化による共有は `compiler/tests/spec_cases/text_views.rs` で、検証用の環境層とサニタイザーを使って検証する。

## C FFI

**[runtime.ffi-types]** extern関数はCの呼出規約を使い、隠れた引数を追加しない。各型は次のC型へ対応する。

| Suz | C |
|---|---|
| `i8`・`i16`・`i32`・`i64` | `int8_t`・`int16_t`・`int32_t`・`int64_t` |
| `u8`・`u16`・`u32`・`u64` | `uint8_t`・`uint16_t`・`uint32_t`・`uint64_t` |
| `f32`・`f64` | `float`・`double` |
| `bool` | `_Bool` |
| `_int`・`_uint` | `int`・`unsigned int` |
| `_long`・`_ulong` | `long`・`unsigned long` |
| `_size_t` | `size_t` |
| `_char` | `char` |
| `void`（戻り値のみ） | `void` |
| `*const void`（引数のみ） | `const void *` |
| `*const T`・`*T`（引数のみ） | 対応するC型への`const T *`・`T *`。C構造体にはヘッダーの`struct`型を使う |

型照合にはCの型互換性を使い、サイズが同じだけでは一致扱いにしない。引数はSuzの通常の関数と同じ順序で、それぞれ1回評価する。C関数の戻り値をそのまま受け取り、Suzのエラー値への変換はラッパー関数が行う。

**[runtime.ffi-struct]** externで宣言した構造体の実体には、ヘッダーのC構造体型をそのまま使う。Suz内部名はその型のtypedefとし、フィールドにはヘッダーのメンバー名でアクセスする。配置の照合用に生成する構造体は実体の保存には使わない。同じ配置を持つ別の構造体型へキャストすることによるCの型に基づく別名規則の違反を避ける。

**[runtime.ffi-borrow]** Arenaの実体を渡すときは、そのアドレスをCの仮引数へ渡し、変換用の領域やコピーを作らない。数値型は既存のC表現、C構造体はヘッダーの型を使う。呼び出しのためにArenaの寿命を変更せず、Cによる解放や参照保持を監視する処理も追加しない。保持期間は [ffi.borrow](spec.md) と [ffi.keep](spec.md) の契約に従う。keepの有無でCの型や呼び出し方法は変えない。

**[runtime.ffi-range]** C固有型の整数範囲には `INT_MIN`・`INT_MAX`・`UINT_MAX`・`LONG_MIN`・`LONG_MAX`・`ULONG_MAX`・`SIZE_MAX`・`CHAR_MIN`・`CHAR_MAX` を使う。C固有型またはexternを使うプログラムには整数幅64ビット以下を要求し、生成Cで検査する。これらを使わないプログラムにFFIの制約は課さない。リテラルの範囲はCコンパイル時、値の変換の範囲は評価時に検査する。`_char`の符号は対象環境に従う。変換失敗時には範囲外のCキャストを実行せず、`as%`もCの符号付き狭小化の処理系依存動作に頼らず値を作る。

**[runtime.ffi-contract]** C側と呼び出し側はそれぞれC APIの契約を守らなければならない。プログラマーは呼び出し側の引数、実体の寿命、読み書きの範囲、必要な同期も保証する。Suzのtrustedは外部コードのメモリ破壊や未定義動作を防止しない。安全なSuz関数として公開するラッパーの実装者は、その公開APIからC APIの契約違反が起きないようにする責任を持つ。

**[runtime.ffi-bytes]** `c_bytes`はインターン済みの文字列の実体、またはtextの参照範囲の先頭を返す。新しいバッファや所有者を作らない。実体はプロセス終了まで保持し、C側に所有権を移さない。Cが呼び出し後も保持することを認めるが、変更・解放・渡された範囲外へのアクセスは契約違反である。NUL終端の保証はなく、埋め込みNULも含めて長さを渡す。

`c_byte_len`は実体またはビューのバイト数を読み、`SIZE_MAX`以下であることを確認して`size_t`へ変換する。超える場合は [rt.ffi-byte-len] に従う。64ビットのsize_tでは保存された64ビットの長さをすべて表せるため、範囲検査を生成しなくてよい。取り出し自体にメモリの確保や文字列のコピーは不要である。

## 作業領域arena

**[runtime.arena]** [rt.arena-storage] と [rt.arena-allocation] の作業領域は、環境層の `suz_env_alloc` でブロックごとに確保する。各ブロックに管理情報と `max_align_t` に整列したデータ領域を置く。管理情報を含む要求サイズがCの `size_t` に収まらない場合は計算のあふれとして拒否し、値を切り詰めない。

ブロックは列として保持する。現在のブロックより後ろは回収済みであり、要求が現在のブロックに収まらなければ、後続から収まるブロックを選んで現在位置の直後へ移す。小さくて選ばれなかったブロックも後続に残して再利用する。適合するブロックがなければ、設定に従って新しいブロックを直後に追加する。既存のデータ領域にreallocは行わない。

領域進入時のブロックと使用位置を生成Cのローカル値に保存し、退出時に復帰する。現在のブロックが変わった場合だけ、データ領域と容量の参照も戻す。内容の消去や参照の走査、環境層への解放は行わない。寿命の検査はコンパイラの責務である。通常ビルドでは、ランタイムの内部APIだけで回収済みの実体への参照を検出しない。ASanビルドでの補助的な検出は [runtime.arena-poison] に従う。

生成Cでは保存した位置にClangの`cleanup`属性を付け、通常終了・return・ループ脱出・エラー回復のgotoで`suz_arena_restore`を呼ぶ。戻り値を評価してから回収する。保存・復帰と、現在のブロック内で完了する確保は常にインライン化する。整列の余白はビット演算で求め、ブロックの再利用・追加確保・失敗時診断は通常経路から分離する。

確保位置（現在のブロック、データ領域、容量、使用位置）は、生成Cの翻訳単位内だけで使う静的変数に置く。全Suz関数がこの変数を使い、関数呼び出しや再帰でも同じ位置から確保する。そのアドレスは外部へ渡さず、ランタイムの拡張関数には現在のブロックを値で渡し、新しい確保位置を値で受け取る。外部関数が確保位置を書き換える可能性をなくし、Cコンパイラが通常経路で状態をレジスタに保持できるようにする。この内部APIは、Suzの生成Cを1つの翻訳単位にまとめる構成を前提とする。

mainのデフォルトarenaもこのストレージを使う。Suz関数・メソッド・関数値・クロージャの呼び出しに領域引数を追加せず、関数のシグネチャによる保存位置の巻き戻しも行わない。明示的なarenaの退出時に保存位置へ戻し、main終了時にデフォルトarenaを回収する。デフォルトarenaの存在だけではブロックを確保せず、確保処理を必要とするプログラムに [rt.arena-storage] の初期容量・拡張・上限を適用する。

`--arena-grow 0`の生成Cではブロックが変わらないため、保存・復帰を使用位置だけに限定する。容量不足の経路も、復帰しないパニック関数へ直接つなぎ、拡張可能な場合に必要なブロックの再読込みを残さない。


**[runtime.array]** 配列の要素列は要素型の整列を満たす1つのArena実体に置く。生成Cの配列参照は、要素列の先頭位置と各次元の長さを値として保持する。行や切り出しの取得では先頭位置と寸法を変え、別のArena実体を確保しない。次元数はコンパイル時に分かるため、各アクセスは使用する次元数に比例した位置計算で行い、要素を走査しない。

位置計算の前に [array.layout]・[array.index]・[array.slice] の条件を満たすことを確認する。負の添字を符号なしへ切り詰めてから比較したり、範囲外のCポインタを作ってから検査したりしてはならない。空配列と空の切り出しもSuzでは非nullとして表し、要素を読み書きしない。要素数0の配置と部分参照の計算で、Cのnullポインタに対する算術や、実体の範囲を越えたポインタの生成を行ってはならない。内部の空配列の表現を理由に、Suzの寿命検査を省略しない。

**[runtime.arena-poison]** `SUZ_CFLAGS=-fsanitize=address` でASanを有効にした場合、Arenaの未使用・回収済みのデータ領域をASanの毒でアクセス禁止にする。ブロックの管理情報は対象外とする。新しいブロックのデータ領域は全体を毒にし、実体の確保時にその実体の範囲だけを解除する。初期値は解除後に格納する。

対応環境（macOS・Apple Silicon）のASanの単位は8バイトとする。ASanビルドでは、実体の先頭を型の要求する整列と8バイトの大きい方に揃え、消費サイズを8バイトの倍数へ切り上げる。別の実体とASanの単位を共有せず、実体の後ろの余白は毒のままにする。丸めによる計算のあふれは [rt.arena-allocation] のエラーとする。余白もArenaの容量を消費するため、通常ビルドより多くの容量を必要とする場合がある。

Arena退出時には、保存位置以後の回収対象を再び毒にしてから、通常どおり確保位置を戻す。複数のブロックにまたがる場合も、保存位置から退出時の現在ブロックまでを処理し、生存中の外側の実体は毒にしない。回収領域は再利用し、再確保した実体の範囲を解除する。領域を保持したまま使い捨てにはしない。

毒が残る範囲への読み書きをASanで計測されたコードが実行すると、ASanが診断する。実行しなかったアクセスや、再利用して毒を解除した後の古いポインタによるアクセスは検出できない。ASanを有効にしていない外部コードのアクセスも保証の対象外である。Suzの型・寿命検査や [ffi.trusted]・[ffi.keep] の契約を置き換えるものではない。

これらの処理と配置の変更は、CコンパイラがASanの有効化を示す場合（`__has_feature(address_sanitizer)` または `__SANITIZE_ADDRESS__`）だけ適用する。通常ビルドには毒の管理処理やASan用の余白を加えない。
