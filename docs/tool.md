# Suz ツール仕様

文書の役割と編集時の判断基準は[仕様の執筆・レビュー基準](spec-writing.md)を参照すること。

この文書は、`suz` コマンドの利用方法と配布物の契約を定める。言語の動作は[言語仕様](spec.md)、生成プログラムの動作は[ランタイム仕様](runtime.md)に従う。規則名には `tool.` を使う。

## 1. 配布と外部ツール

**[tool.distribution]** 配布物は、対象OS・CPU向けの実行ファイル `suz` 1つである。コンパイラ、ランタイム本体、標準環境層、Ryu、そのライセンス表示に必要なデータを内包する。実行ファイルを移動した後も、その場所や元のソースツリーに依存せず動作する。

**[tool.c-compiler]** 実行ファイルの生成には、外部のClangと対象環境のSDKを使う。`--cc PATH` を指定した場合はその実行ファイルを使い、省略した場合は `PATH` 上の `clang` を使う。指定できるのはC23に対応したClangだけである。指定値は1つの実行ファイルのパスとして扱う。Clangの引数はSuzが構成し、シェルを介さず起動する。対応環境は `[tool.platform]` で定める。

**[tool.prerequisites]** `build` と `run` は、処理の開始時にClang・リンカー・SDKが利用できることを確認する。指定コンパイラがC23と128ビットの `_BitInt` に対応したClangでない場合は、[tool.c-compiler] の英語の診断を表示し、終了コード2で終了する。

Clang・リンカー・SDKが不足する場合は、不足しているものと導入方法を標準エラーに表示し、終了コード2で終了する。macOSではXcode Command Line Toolsの導入方法として `xcode-select --install` を案内する。コンパイラが見つからない場合とSDKが見つからない場合は、診断を区別する。外部ツールのインストールは利用者が行う。

`check` と `emit-c` は、外部ツールを用意せず実行できる。

**[tool.platform]** 対象環境は次のとおりである。OSとClangのバージョンは、コンパイラ・ランタイムを実際に検証した値である。

| 項目 | 対象環境 |
|---|---|
| OS | macOS 26.5（25F71） |
| CPU | Apple Silicon（arm64） |
| Cコンパイラ | Apple Clang 21.0.0（clang-2100.1.1.101） |
| SDK | 上記Clangで対象のmacOS実行ファイルをリンクできるmacOS SDK |

macOSではXcodeまたはCommand Line ToolsでClang・リンカー・SDKを用意する。

## 2. コマンド

**[tool.commands]** 次のコマンドを提供する。`INPUT` はSuzソースファイル1つである。

```text
suz build INPUT -o OUTPUT [OPTIONS]
suz run INPUT [OPTIONS]
suz check INPUT [OPTIONS]
suz emit-c INPUT -o DIRECTORY [OPTIONS]
suz --version
suz --help
suz --licenses
```

**[tool.arguments]** コマンド名の後では、入力ファイルとオプションの順序は自由である。値を取るオプションは、次の引数を値として読む。`--` より後の引数はファイル名として扱う。未知のコマンド・オプション、必須引数の欠落、入力の重複、同じオプションの重複、排他的なオプションの併用はツールエラーである。引数なしの起動もツールエラーとし、標準エラーへ使用方法を表示する。

**[tool.nesting-guarantee]** 対応環境（[tool.platform]）では、[src.nesting-limit] の上限以内のソースに対して、`check`・`build`・`run`・`emit-c`は構文の深さによるスタック枯渇で異常終了しない。生成したCも、[tool.build-settings]の設定と`-O0`・`-O2`で、Clangのスタック枯渇による異常終了や`stack nearly exhausted`の警告を起こさずコンパイルできる。上限超過のソースは、深さ10000でも構文解析中に拒否し、検査・定数評価・C生成へ渡さない。入力全体の大きさによるメモリ不足は保証に含めない。

### 2.1 build

**[tool.build]** 入力を検査し、Cへ変換し、同梱ランタイム・環境層とリンクした実行ファイルを `OUTPUT` に作成する。`-o` は必須である。

```sh
suz build program.suz -o program
suz build program.suz -o program -O2
```

### 2.2 run

**[tool.run]** 入力を一時領域でビルドし、生成した実行ファイルを1回実行する。生成プログラムの作業ディレクトリは、`suz run` を呼んだ作業ディレクトリである。標準入力・標準出力・標準エラーはそのまま引き継ぐ。正常終了とパニックの終了コードは、生成プログラムの値をそのまま返す。

**[tool.run-signal]** 対応するUnix環境では、生成プログラムがシグナルで終了した場合、後処理の後に `suz run` 自身も同じシグナルで終了する。端末からの割り込みは生成プログラムにも届くようにする。

```sh
suz run program.suz
```

### 2.3 check

**[tool.check]** 入力に対して字句・構文・名前解決・型・定数評価・制御・診断設定の検査を行う。成功時は終了コード0を返す。このコマンドはClangやSDKの用意に依存せず使える。

```sh
suz check program.suz
```

### 2.4 emit-c

**[tool.emit-c]** 生成したCの調査や、独自の環境層とのリンクに必要な一式を `DIRECTORY` に出力する。ビルドスクリプトは `-std=c23` を使う。`CC` に指定できるのはC23に対応したClangだけであり、必要な機能は [runtime.c-check] で検査する。出力内容は次のとおりである。

| パス | 内容 |
|---|---|
| `program.c` | 入力から生成したC |
| `LICENSE-MIT`・`LICENSE-APACHE` | Suzのライセンス |
| `runtime/` | 同じSuzバイナリに同梱されたランタイム・環境層・Ryu・ライセンス |
| `scripts/build-c.sh` | 数値設定を固定して、この一式から実行ファイルを作るコマンド |

```sh
suz emit-c program.suz -o generated
cd generated
./scripts/build-c.sh program.c -o program -O2
```

## 3. オプション

**[tool.options]** コマンドごとに次のオプションを受け付ける。

| オプション | build | run | check | emit-c | 意味 |
|---|---|---|---|---|---|
| `-o PATH` | 必須 | | | 必須 | 出力先 |
| `-O0`、`-O2` | 可 | 可 | | | 最適化。既定は `-O0` |
| `--cc PATH` | 可 | 可 | | | Clangの実行ファイル |
| `--env FILE` | 可 | 可 | | 可 | 標準環境層を置き換えるCソース |
| `--include-dir DIR` | 可 | 可 | 可 | 可 | Cヘッダーの探索先を追加。複数指定可 |
| `--library-dir DIR` | 可 | 可 | 可 | 可 | ライブラリの探索先を追加。複数指定可 |
| `--link-library NAME` | 可 | 可 | 可 | 可 | Cライブラリ名を指定。複数指定可 |
| `--link-object FILE` | 可 | 可 | 可 | 可 | オブジェクトまたはアーカイブを指定。複数指定可 |
| `--log-arena` | 可 | 可 | | 可 | 作業領域の使用量を計測。既定は無効 |
| `--log-arena-format FORMAT` | 可 | 可 | | 可 | summary/tree/tree-bytes/csv。既定はtree |
| `--log-arena-limit COUNT` | 可 | 可 | | 可 | 計測ツリーの最大行数。根を含め既定256 |
| `--arena-initial SIZE` | 可 | 可 | | 可 | 作業領域の初期容量。既定は `64M` |
| `--arena-grow SIZE` | 可 | 可 | | 可 | 作業領域の追加容量の基準。既定は `64M`、`0` は拡張禁止 |
| `--arena-limit SIZE` | 可 | 可 | | 可 | 確保した作業領域の総容量上限。既定は `unlimited` |
| `--symbol-pool-limit SIZE` | 可 | 可 | | 可 | シンボルプールの上限。既定は `1G` |
| `--force` | 可 | | | | 既存の通常ファイルを出力先として置き換える |
| `--log-ignore` | 可 | 可 | 可 | 可 | 実行されたignoreの位置と理由を記録する。既定は無効 |
| `--log-level LEVEL` | 可 | 可 | 可 | 可 | 生成するログの最低レベル。既定はinfo |
| `--log-allow` | 可 | 可 | 可 | 可 | 抑えた警告と理由を表示する |
| `--warn-unhandled-arithmetic` | 可 | 可 | 可 | 可 | 整数演算の失敗処理がない箇所を警告する |

| `--help` | 可 | 可 | 可 | 可 | そのコマンドの使用方法を表示する |

`-O0` と `-O2` は併用できない。`--warn-unhandled-arithmetic` と `--deny-unhandled-arithmetic` も併用できない。診断設定の意味は言語仕様の `[diagnostic.arithmetic]` に従う。設定を省略した場合は通常設定である。`[diagnostic.constant-comparison]` と `[diagnostic.integer-division-to-float]` の警告は、これらの整数演算の診断設定にかかわらず有効である。

**[tool.environment]** `--env` のCソースは、ランタイム仕様の環境関数を実装する。`build` と `run` はそのファイルを標準環境層の代わりにリンクする。`emit-c` はその内容を出力先の `runtime/suz_env.c` に収録する。環境層のコンパイルには同梱の `suz_env.h` を使う。

**[tool.build-settings]** C23と厳密な浮動小数点演算を使い、積和の縮約を停止し、非正規化数をIEEEの規則で扱う。Clangへの数値関連オプションはSuzが固定する。具体的には `-fhonor-nans`、`-fhonor-infinities`、`-ffp-contract=off`、`-fdenormal-fp-math=ieee` を指定する。`CFLAGS`、`CPPFLAGS`、`LDFLAGS` に空でない値がある場合、`build` と `run` はツールエラーにする。追加のフラグは [tool.extra-flags] で渡す。

**[tool.extra-flags]** `build`、`run` と、`emit-c` が出力する `scripts/build-c.sh` は、環境変数 `SUZ_CFLAGS` から次のフラグを受け付ける。

| フラグ | 用途 |
|---|---|
| `-march=値`、`-mcpu=値`、`-mtune=値` | 対象CPUの指定 |
| `-g` | デバッグ情報 |
| `-fno-omit-frame-pointer` | プロファイラ |
| `-flto`、`-flto=thin`、`-flto=full` | リンク時の最適化 |
| `-fprofile-instr-generate`、`-fprofile-instr-generate=パス`、`-fprofile-instr-use=パス` | 実行の記録を使う最適化 |
| `-fsanitize=値` | `address` と `undefined` のカンマ区切り |

値はASCIIの空白（スペース・タブ・改行・復帰・垂直タブ・改ページ）で区切る。空の項目は無視する。引用符・バックスラッシュ・変数・コマンド・ワイルドカードの展開は行わないため、空白を含むパスは渡せない。`=` の後の値は空にできない。許可リストにないフラグは、その項目を示してツールエラーにする。CPU名やPGOファイルの有効性など、受け付けた値の検証はClangが行う。値が不正な場合、`build` と `run` はClangの診断を表示し、ビルド失敗（終了コード4）として報告する。コンパイラとSDKの能力確認には追加フラグを使わない。

CLIと出力用スクリプトは同じ許可リストを使う。受け付けた引数は、Suzが固定するフラグの前に置く。生成Cとランタイムのコンパイル・リンクは1回のClang呼び出しで行い、リンクにも同じフラグを適用する。

**[tool.size]** 容量の数値はASCIIの正の10進整数で書く。単位なしはバイト、大文字の`K`・`M`・`G`はそれぞれ1,024・1,048,576・1,073,741,824倍とする。単位換算はオーバーフローを検査してから使う。負数、不正な表記、換算後に64ビット符号なし整数の範囲を超える値、値の省略、同じオプションの重複はツールエラーである。`0`と`unlimited`を使えるかは各オプションの規則に従う。

### 3.1 シンボルプールの上限

シンボルプール全体の容量と、一つの `symbol` の個数上限は別である。`unlimited` や `2G` 以上を指定しても、Unicodeスカラー値が2^31−1個を超える `symbol` の生成は [rt.len-limit] によりパニックする。

**[tool.symbol-pool-limit]** `--symbol-pool-limit SIZE` は、生成するプログラムのシンボルプールの上限を指定する。`build`、`run`、`emit-c` で受け付ける。省略時は `1G` とする。設定は生成するプログラムに組み込む。`emit-c` では設定を生成物に含め、そのCから作った実行ファイルにも適用する。

**[tool.symbol-pool-size]** SIZEは [tool.size] に従う。`unlimited`は無制限とし、`0`は認めない。既定の1Gは1 GiB（1,073,741,824バイト）である。無制限でも実行環境のメモリや長さの表現範囲には制約される。計測対象は [runtime.symbol-accounting] に従う。静的なtextと作業領域に置くtextは、このプールの上限に含めない。作業領域の容量は、この文書の「作業領域の容量」に従う。

```sh
suz build program.suz -o program --symbol-pool-limit 256M
suz run program.suz --symbol-pool-limit 2G
suz emit-c program.suz -o generated --symbol-pool-limit unlimited
```

### 3.2 作業領域の容量

**[tool.arena-capacity]** `--arena-initial SIZE` は起動時の初期容量、`--arena-grow SIZE` は追加確保する容量の基準、`--arena-limit SIZE` は確保済みブロックの総容量の上限を指定する。`build`・`run`・`emit-c`で受け付け、既定値は順に `64M`・`64M`・`unlimited` とする。64Mは64 MiB（67,108,864バイト）である。

SIZEは [tool.size] に従う。initialとgrowでは単独の `0` も許す。initialの0は初期確保なし、growの0は追加確保禁止であり、両方0なら実体の確保は成功しない。limitでは `unlimited` を許し、0は拒否する。

有限のlimitがinitialより小さければ、初期確保をlimitまでに抑える。追加確保量はgrowと単一要求サイズの大きい方を基準とし、上限までの残量で抑える。残量が要求サイズに満たなければパニックする。growが0でも、既に確保して回収した領域は再利用できる。実体を複数のブロックに分割しないため、空き容量の合計が要求以上でも、1つのブロックに収まらず追加確保もできなければ失敗する。

上限は整列の余白と回収後に保持する容量も含む、各ブロックのデータ容量の合計に適用する。ブロックの管理情報と環境層の確保管理費用は含めない。無制限でもOSの確保失敗やサイズ計算のあふれはパニックする。

設定は生成Cに埋め込み、入れ子を含む全作業領域で使用する。`emit-c`後も同じ設定を使う。作業領域未使用なら、この設定によるメモリ確保は行わない。`check`は3つのオプションを受け付けない。失敗時の診断は [rt.arena-storage]・[rt.arena-allocation] に従う。

### 3.3 作業領域の使用量の計測

**[tool.log-arena]** `--log-arena`は値を取らないフラグで、`build`・`run`・`emit-c`で受け付ける。省略時は計測しない。`check`では受け付けない。重複指定は終了コード2のツールエラーとする。`emit-c`には計測を有効にしたCを出力する。最低ログレベルとは独立しており、`--log-level off`でも計測結果を出力する。

**[tool.arena-report-format]** `--log-arena-format FORMAT`で表示形式を選ぶ。`--log-arena`との併用を必須とし、順序は問わない。オプション直後の値の欠落・不正な値・重複指定と、`check`での指定は終了コード2のツールエラーとする。形式は`summary`・`tree`・`tree-bytes`・`csv`から選び、省略時は`tree`とする。`summary`は [tool.arena-report-output] の全体集計をバイト単位の整数で表示する。他の形式は [tool.arena-tree-output] に従う。

**[tool.arena-report-limit]** `--log-arena-limit COUNT`は、計測用ツリーの最大行数を指定する。根の行を含み、既定は256とする。値はASCIIの10進整数で1〜65535とし、符号や単位は付けない。`--log-arena`との併用を必須とする。値の欠落・不正な値・重複指定と、`check`での指定は終了コード2のツールエラーとする。`summary`ではツリーを記録しないため、この上限は使用しない。計測対象の作業領域の容量を制限するオプションではない。

```sh
suz build game.suz -o game -O2 --log-arena --log-arena-format summary
./game
# arena peak=3145776 reserved=67108864 blocks=1 expansions=0
suz build game.suz -o game -O2 --arena-initial 3145776 --arena-grow 0 --force
```

ツリーは、どの作業領域でメモリを使っているかを調べるために使う。

```text
arena                 function  peak
main                  main        56
├── tree.suz:2:5      a           56 [recursive]
│   └── tree.suz:8:5  b           48 [recursive]
└── tree.suz:16:9     main        16
    └── tree.suz:2:5  a            8
reserved=128 blocks=1 expansions=0
```

これは`tree-bytes`の表示例である。`recursive`は再帰を折り畳んだ行、`omitted`は記録上限のため子の枝を省略した行を示す。省略しても、その親と根のpeakには省略した枝の使用量を含む。子のpeakは同時に発生するとは限らず、合計しても親のpeakにはならない。容量設定には根のpeakを使う。

測定した実行と同じ確保・回収の経路では、`peak`を初期容量に指定して追加確保なしで実行できる。入力によって経路や配列の大きさが変わる場合は、その分の余裕を持たせること。ASanの有無を含め、実際に使うビルドと同じ設定で測ること。

**[tool.arena-report-resources]** ツリーの記録・検索・出力に使うメモリは作業領域と別に、mainの実行前に一度だけ確保し、mainの終了時に解放する。summaryではこのメモリを確保しない。計測結果の出力中は動的確保やシンボルプールへの登録を行わない。確保や反復のたびに祖先・兄弟を走査しない。実装は [runtime.arena-report] に従う。

#### 3.3.1 計測値と出力

**[tool.arena-report]** [tool.log-arena] が有効な場合、Suzのmainから戻った後、デフォルトの作業領域を回収する前に使用状況を出力する。対象はデフォルトの作業領域と、その内側の全作業領域への実体の確保である。実体の確保を一度も実行しなかった場合は出力しない。初期ブロックを確保しただけの場合も出力しない。パニック・異常終了時には出力しない。

**[tool.arena-peak]** `peak`は、実体を単一ブロックへ順に置いたと仮定した使用位置の最大値である。確保ごとに整列の余白と実体の大きさを加え、明示的な作業領域への進入時に使用位置を保存し、退出時に戻す。関数呼び出しだけでは戻さない。途中脱出でも通常の回収と同じ範囲を戻す。ASan有効時は [runtime.arena-poison] の整列と丸めを適用する。計算のあふれは確保位置で [rt.arena-allocation] のパニックとする。

`peak`は、同じ実行の経路で追加確保なしに実体を置くために必要な最小の初期容量を表す。実際のブロック境界で残る未使用部分とブロックの管理情報は含まない。`reserved`は確保したブロックのデータ容量の合計の最大値、`blocks`は確保したブロック数、`expansions`は起動時の初期確保の後に追加したブロック数とする。初期容量0の場合、最初の実体のためのブロック確保もexpansionsに含む。回収したブロックの再利用ではblocks・expansionsを増やさない。

**[tool.arena-report-output]** 計測結果は標準エラーへ出力し、各行の末尾にLFを付ける。ソース位置や通常ログの接頭辞は付けない。1回の計測結果の途中に別のログ出力を挟まない。

`summary`形式は `arena peak=N reserved=N blocks=N expansions=N` の1行とする。値はバイト数または個数の10進整数である。

**[tool.arena-tree]** ツリーの根はmainのデフォルトの作業領域とする。明示的な作業領域を開いたとき、実行時に現在の作業領域となっている行の子として記録する。通常の関数呼び出しだけでは行を作らない。同じ親の下にある同じソース位置（ファイル・行・列）の作業領域は同じ行に集約し、別の親の下では別の行にする。汎用関数の具体化が違っても、同じソース位置なら同じ規則で集約する。確保のなかった作業領域も、進入を実行した場合は行を記録する。ただしプログラム全体で確保がなければ [tool.arena-report] に従って何も出力しない。

各行のpeakは、作業領域への進入時点から増えた仮の使用量の最大値とする。子の使用分と整列の余白も含む。同じ行に集約した各回の最大値を保持する。子の最大値を合計した値ではない。根は [tool.arena-peak] の値とする。

**[tool.arena-tree-recursion]** 同じソース位置が実際にアクティブな進入の祖先にあれば、新しい行を作らず、その祖先の行へ集約してrecursiveを真にする。行のpeakは、その行に集約される最も外側の作業領域への進入時点を基準とする。相互再帰にもこの規則を適用する。

**[tool.arena-tree-limit]** 行数が [tool.arena-report-limit] に達した場合、新しい行は作らず、その親のomittedを真にする。その進入の内側はまとめて記録対象外とし、別の親へ子を付け替えたり、再帰の集約先へ飛び越えたりしない。記録済みの行への再進入は引き続き集計する。省略した枝の使用量も、記録済みの祖先と根のpeakに含める。

**[tool.arena-report-storage]** 計測用のメモリはpeak・reserved・blocks・expansionsに含めない。計測用のメモリを確保できない場合はmainの宣言位置で [rt.arena-report-storage] のパニックとし、利用者のmainは実行しない。

**[tool.arena-tree-output]** 行の識別子は記録順の0始まりの整数とし、根は0とする。出力は深さ優先で、兄弟の順序は初めて記録した順とする。各行に作業領域のソース位置、作業領域を開いた関数名、peakを示す。メソッドは読み取り・書き込みのどちらも`型名.メソッド名`とし、型引数は表示しない（例：`Pt.bump`、`Box.get`）。汎用関数も型引数を表示せず、ソース上の関数名を使う。クロージャの関数名は囲む関数名に`::<closure>`を付け、入れ子の深さだけ繰り返す。

`tree`と`tree-bytes`は枝を罫線で表し、関数名の開始位置とpeakの右端を全行で揃える。根の位置欄は`main`、他は`ファイル:行:列`とする。テキスト表のパスと関数名では、制御文字・非ASCIIバイト・逆斜線を`\xHH`（小文字の16進数）にして改行や桁ずれを防ぐ。`tree`は1024未満を整数のB、1024以上1 MiB未満をKiB、それ以上をMiBで表示する。KiB・MiBは小数1桁に四捨五入する。`tree-bytes`は単位なしの整数バイト数を表示する。再帰を集約した行に`[recursive]`、子を省略した行に`[omitted]`を付ける。末尾に`reserved=N blocks=N expansions=N`を1行だけ出力する。

`csv`の列は`id,parent,depth,source,line,column,function,peak,recursive,omitted,reserved,blocks,expansions`とし、先頭にこのヘッダーを出力する。sourceとfunctionは元のUTF-8を二重引用符で囲み、内部の二重引用符を2個にする。数値は10進整数、真偽値は`true`・`false`とする。根のparentは空欄とし、reserved・blocks・expansionsは根だけに値を入れ、他の行は空欄とする。根のsource・line・columnはmainの宣言位置とする。CSVに別形式のサマリや注釈行を混ぜない。

## 4. 出力と一時ファイル

**[tool.output]** `build` の既存出力は、`--force` がある場合にだけ置き換える。ディレクトリとシンボリックリンクは置き換え対象にできない。入力ソース、指定した環境層と同じファイルを出力先に指定すると、`--force` があってもエラーである。同一性の判定には、別名やハードリンクによる参照も含める。`emit-c` の出力先には新規ディレクトリを指定する。

**[tool.publish-output]** 成果物を完成させてから最終出力先に反映する。言語の検査、Cのコンパイル・リンク、成果物の準備に失敗した場合は、既存の出力を保持する。`--force` を省略した場合、処理中に別のプロセスが出力先を作成しても上書きしない。

**[tool.temporary]** C、同梱ソースの展開物、中間成果物、`run` の実行ファイルには、呼び出しごとに独立した一時領域を使う。正常終了と処理可能なエラーでは一時領域を削除する。`run` では子プロセスの終了後に削除する。一時領域の名前を診断のSuzソース名として使わず、利用者が指定した入力パスを保持する。

## 5. メッセージと終了

**[tool.log-ignore]** `--log-ignore`は値を取らないフラグで、[err.ignore-output] の記録を有効にする。重複指定はツールエラー（終了コード2）とする。4コマンドで共通の引数を使えるように`check`でも受け付けるが、`check`は実行せず、ignoreの記録も出力しない。警告抑制の理由を表示する`--log-allow`とは独立する。

**[tool.log-level]** `--log-level LEVEL`は、[log.filter]に従って生成するログの最低レベルを指定する。値は小文字の`debug`・`info`・`warn`・`error`・`off`のいずれかとし、省略時は`info`とする。値の欠落・空文字・その他の値・オプションの重複はツールエラー（終了コード2）とする。後勝ちにはしない。

`check`も同じ引数を受け付けるが、ログの検査を省略しない。`emit-c`は設定を適用済みのCを出力するため、そのCをビルドする際に同じオプションを渡す必要はない。コンパイラAPIでの設定は[コンパイラの説明](../compiler/README.md#コンパイラapi)を参照すること。

**[tool.log-allow]** `--log-allow` は [allow.log] に従い、その設定で警告になる箇所のうち `allow` で抑えたものを理由とともに標準エラーへ書く。

**[tool.messages]** ツールのメッセージは英語で出力する。`build`、`check`、`emit-c` の成功時は標準出力を空にする。警告・エラーは標準エラーに出力する。言語の診断は次の形式とし、規則名は言語仕様から使う。

```text
FILE:LINE:COLUMN: MESSAGE [rule]
FILE:LINE:COLUMN: warn: MESSAGE [rule]
```

ツールの使用方法・入出力・外部ツールのエラーは `suz: MESSAGE [tool.rule]` の形式にする。Clangが出力した診断は標準エラーへ伝え、Suzの言語診断と区別する。

本体の違反や呼び出しの連鎖などの関連診断は、主診断に続けて `  note: 行:列: メッセージ [規則名]` の形式で1件ずつ出力する。各行は1つの位置と1つの規則名を持つ。

**[tool.exit]** ツールの終了コードは次のとおりである。

| コード | 意味 |
|---|---|
| 0 | コマンドの成功 |
| 1 | Suzソースのコンパイルエラー |
| 2 | ツールエラー：引数・ファイル入出力・外部ツールやSDKの不足・外部ツールの起動・子プロセスの起動や待機のエラー |
| 3 | Suzの内部エラー |
| 4 | 起動したClangのコンパイル・リンクが失敗した場合 |

`run` で生成プログラムを起動できた場合は `[tool.run]` と `[tool.run-signal]` に従う。プログラムの終了コードとツールのエラーコードは値が重なるため、ツール側の失敗は診断も併せて示す。

**[tool.information]** `--version` は `suz vMAJOR.MINOR.PATCH` の形式で、ツールのバージョンを標準出力に1行で表示する。`--help` と各コマンドの `--help` は、使用方法・オプション・既定値を標準出力に表示する。`--licenses` は、Suzと同梱物の著作権・ライセンス表示を標準出力に表示する。これらは入力ファイルとClangを用意せず実行でき、成功時は終了コード0である。

## 6. C FFIの検査

**[tool.ffi-header]** externで指定したヘッダーを生成Cの `#include <ヘッダー名>` で読み込み、関数ポインタ型の互換性をコンパイル時に検査する。引数の個数・各型・戻り値・可変長引数の有無が一致することを要求し、暗黙変換で呼び出せるだけでは受理しない。ポインタ引数は参照先の型とconstの有無も一致することを要求する。未使用の宣言も照合する。関数形式・オブジェクト形式のマクロは対象外である。ヘッダーがない場合や宣言が一致しない場合はCコンパイルを失敗させる。型不一致とマクロの診断には`[tool.ffi-header]`を付ける。ランタイムと同梱ライブラリのヘッダー探索先には`-iquote`を使い、生成Cとランタイムの`#include "..."`からだけ参照する。externの`#include <...>`の探索先には追加しない。C名の`suz_`接頭辞は [ffi.name] に従い予約する。

externの構造体は、宣言したフィールドを同じ順序で並べた通常のC構造体と、ヘッダーの `struct Cタグ` のサイズ・整列・各フィールドの `offsetof`・型が一致することを要求する。フィールドの型照合ではconst・volatile・atomicの有無も区別する。未使用の宣言も照合し、不一致はCコンパイルエラーにする。構造体タグとフィールド名のマクロは認めない。ヘッダーに存在しない型・フィールドやビットフィールドなど、照合式自体が成立しない場合はCコンパイラの診断に従う。

`check`はSuz側の構文・名前・型・trustedなどを検査する。Cコンパイラを起動しないため、成功してもヘッダーとの整合性やリンク成功は保証しない。`emit-c`も照合コードを出力するだけで、C側の検査は出力物をビルドするときに行う。C固有型のリテラル範囲もCコンパイル時に確定するため、`check`の成功では保証しない。

`build`・`run`は標準のヘッダー探索・リンク環境を使う。標準Cライブラリの通常の関数に追加のリンク指定は不要である。呼び出す関数の実体がなければリンクエラーになる。外部ファイルは次のオプションで指定する。

### 6.1 外部ヘッダーとリンク対象

**[tool.ffi-options]** `--include-dir DIR`はCヘッダーの探索先、`--library-dir DIR`はライブラリの探索先を追加する。`--link-library NAME`はClangの`-lNAME`としてライブラリを選び、`--link-object FILE`は指定したオブジェクトまたはアーカイブをリンカーへ直接渡す。Cソースをコンパイルする指定ではない。各オプションは値を1つ取り、複数回指定できる。

値の省略・空文字列・`-`で始まる値はツールエラー（終了コード2）である。`-`で始まる相対ファイル名は`./`を付けて書く。ライブラリ名にはASCIIの英数字・`_`・`+`・`.`・`-`だけを使い、接頭辞`lib`と拡張子を除いた名前を書く。例えば`libexample.a`を探索する指定は`--link-library example`である。パス中の空白・引用符などは呼び出し元のシェルで引用し、Suzは展開や分割をしない。

**[tool.ffi-order]** 探索先は指定順にClangへ渡す。ライブラリとオブジェクトは分けて並べ替えず、重複も除去せず、指定した相互の順序を保持する。生成C・同梱ランタイムの入力の後ろにこれらを渡し、その後ろにSuzが必要とする標準ライブラリを追加する。静的ライブラリを再探索するかなどのリンク動作は、対象環境のリンカーに従う。

```sh
suz build main.suz -o app \
    --include-dir vendor/include \
    --library-dir vendor/lib \
    --link-object bridge.o \
    --link-library example
```

**[tool.ffi-path]** 相対パスの基準は、Suzコマンドを実行した時点の作業ディレクトリとする。入力ソースのあるディレクトリではない。各パスは存在確認せず絶対パスへ変換する。ヘッダーがない場合はCコンパイル、オブジェクト・ライブラリ・必要な関数の実体がない場合と競合する実体を与えた場合はリンクで失敗する。`build`・`run`はClangの診断を表示して終了コード4を返す。失敗したビルドの実行ファイルは公開しない。

**[tool.ffi-export]** `emit-c`は上記の引数を、順序と値を保って出力先の`scripts/build-c.sh`に保存する。パスはemit-c実行時に絶対パス化した値を保存するため、出力ディレクトリを移動したり別の作業ディレクトリからスクリプトを実行したりしても、元の外部ファイルを参照する。ヘッダー・オブジェクト・ライブラリはコピーしない。別の環境へ配布する場合は外部ファイルを別途用意し、スクリプト冒頭の`ffi_args`のパスを変更する。

ビルドスクリプトも同じ4オプションを受け付ける。その相対パスはスクリプトを実行した時点の作業ディレクトリ基準で、保存済み引数の後ろに追加する。保存済み引数の置き換えや削除はしない。

**[tool.ffi-check]** `check`も同じオプションを受け付け、値の形式だけを検査する。外部ファイルの存在、ヘッダーの内容、リンク結果を検査せず、Clangを必要としない。`emit-c`も外部ファイルを読み込まず保存だけを行う。C側の検査は生成物をビルドする時点で行う。

## 7. サニタイザーと処理量

ASanを有効にすると、作業領域への確保時に確保範囲のアクセス禁止を解除し、回収時には回収範囲を再びアクセス禁止にする。通常実行の確保位置の復元に加え、処理する範囲とブロック数に応じた管理処理が発生する。複数ブロックにまたがる回収では途中のブロックの未使用部分を含む場合がある。この処理を通常実行のO(1)の回収と同じコストとして見積もらないこと。配置と処理範囲は [runtime.arena-poison](runtime.md) を参照すること。
