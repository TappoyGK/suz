# Suz 仕様例集

文書の役割と編集時の判断基準は[仕様の執筆・レビュー基準](spec-writing.md)、仕様例集とRust結合テストの配置基準は[ソースの開発規約](development.md#検証する内容)を参照すること。

[言語仕様](spec.md)に対する受理・拒否・実行結果の確認例。期待結果は仕様から導いたものであり、Suzコンパイラでの実行結果ではない。

## 分類とID

例は `spec-cases/` の分野別ファイルに分ける。書式と全体の件数はこのファイルで管理する。

各例には、何を確かめる例なのかを示す主根拠を1つ付け、対象の分野に配置する。関連するほかの規則は補助根拠として記載する。目次の「対応する仕様」には、その分野の例の主根拠が属する章をすべて記載する。

分野は仕様の順に並べ、分野内は主根拠の掲載順を基本とする。同じ主根拠の例は、基本的な動作、境界条件、ほかの機能との組み合わせの順にまとめ、対応する受理例とエラー例を近くに置く。

IDは分野の接頭辞と番号で構成し、期待結果の種類を含めない。採番はリリース時に固定し、リリース済みのIDは振り直さない。リリース前は新規追加分の掲載順や欠番を整理して採番し直せるが、Rust結合テストへ移管した例のIDはリリース前であっても再利用せず、末尾の[欠番一覧](#欠番一覧)に記録する。採番し直す際は、文書内のファイル名や実行対象IDの参照も更新する。

1ファイルが概ね1,000行（または50例）を超えたらサブトピック別ファイルへの分割を検討する。ただし、同じ規則の受理・拒否・境界例を数字だけで機械的に分断しない（たとえば `flow-control.md` は制御構文のまとまりを保つため、わずかに目安を超えた構成としている）。

## 読み方と保存方法

通常のソースブロックは、それぞれ独立した1ファイルである。IDをファイル名にし、たとえば `prog-001` は `prog-001.suz` として、コードブロックの先頭を1行目に保存する。改行はLFとする。バイト列を指定した例は、そのバイト列をそのまま保存する。

通常設定での結果を基本とし、診断設定を比較する例には別途指定する。通常終了する例の標準出力は空。標準エラーは記載したログだけで、ログがない例では空。コンパイルエラーの終了コードや診断文言、パニックの診断文言は仕様で固定されていないため、理由と位置を確認する。ただし、診断文言に含める `char` 値の表示は [lit.display] に従う。

バイト列の入力図では、`<CR>`は復帰文字（0d）、`<LF>`は改行文字（0a）、`<FF>`は不正なUTF-8の1バイト（ff）を表す。`<EOF>`はファイルの終端であり、文字やバイトではない。図中の改行は表示のためで、ファイルに含める改行は記号で示したものだけ。

保存用の16進数は、空白と改行を取り除き、2桁を1バイトに変換して各IDの `.suz` ファイルへ保存する。

## 期待結果の書式

### 共通規則

以下の書式規則および書式エラー検査は、例の範囲（`### ID 題名` から次の第3階層以上の見出しまたは文書末尾まで）の内側にだけ適用する。説明用の見出しの下（たとえば `array-basic.md` の概要の節）には適用しない。

- 例の見出しは `### ID 題名` とし（題名は空にできない）、次の同じ階層以上の見出し（`#`・`##`・`###`）または文書末尾までをその例の範囲とする。コードブロック内の見出しは区切りとして扱わない。
- IDを先頭に持つ見出し、または範囲内に `- 主根拠：` を持つ第3階層の見出しを例として扱う。それ以外は説明用の見出しとする。
- IDは、1文字以上の英小文字、ハイフン、001から999までの3桁の番号で構成し、文書内で一意とする。
- 目次表に分野の接頭辞と件数を記載する。結果別件数も表に記載し、どちらも実際の例との一致を検証する。
- 見出しの直後の行から最初の空行（空白だけの行を含む）までをメタ行のかたまりとする。かたまり内には `- 主根拠：`（必須・1行）、`- 補助根拠：`（任意・1行まで）、`- 結果` 行（必須・1行以上）だけを置き、それ以外の行は置けない。かたまりより後の説明文は機械的に解析しないため箇条書きや表を書けるが、行頭の空白を除いて `- 主根拠：`・`- 補助根拠：`・`- 結果：`・`- 結果（` で始まる行はかたまり外に置けない。
- `- 主根拠：` に続けて `` `[規則ID]` `` を前後の空白や末尾の句点なしで1つ書く。`- 補助根拠：` には `` `[規則ID]` `` を `・` または `、` でつないで書き、同じIDの重複や主根拠と同じIDの記載は不可とする。主根拠および結果行の診断・警告に書く規則IDは言語仕様（`docs/spec.md`）に、補助根拠の規則IDは `docs/spec.md` またはランタイム仕様（`docs/runtime.md`）に存在する規則でなければならない。
- ラベルは `**標準エラー：**` のように独立した行に太字で書き、次のコードブロックまで空行だけを置く。
- 最初の `suz` コードブロックに限り `**ソース：**` ラベルを省略できる。通常のソースブロックは空にできない。それ以外の未ラベルブロック（`~~~` や字下げされたフェンスを含む）および未知の太字ラベル（`**…：**`）は置けない。

各例はメタ行のかたまり、空行、説明文（任意）、入力、実行時出力（任意）の順に記載する（書式エラーとして強制するのはメタ行のかたまりの位置だけで、それ以降の並び順自体はエラーにしない）。

### 入力

次のいずれかを指定する。

| ラベル | 形式 | 内容 |
|---|---|---|
| （省略可、または `**ソース：**`） | `suz` ブロック | 通常のソース |
| `**保存用のバイト列（16進数）：**` | `text` ブロック | 生バイトの入力 |

「入力図」は任意で1つまで置ける。直後に `text` ブロックを置き、末尾に `<EOF>` を1つ記載する。前述の記号をバイト列に復元し、入力との一致を検証する。

### 結果行

従来の表形式（`**期待結果：**`・`**コンパイル診断：**`・`**パニック診断：**`・`**警告：**`）は廃止し、単一設定・複数設定を問わず `- 結果` の箇条書き行で期待結果を記述する。

| パターン | 書き方 | 解釈 |
|---|---|---|
| 正常終了（終了コード0・警告0） | `- 結果：正常終了` | 設定=通常、終了コード=0、警告数=0 |
| 正常終了（終了コード非0） | `- 結果：正常終了 1` | 設定=通常、終了コード=1、警告数=0 |
| コンパイルエラー | ``- 結果：コンパイルエラー `[規則ID]` 行:列`` | 設定=通常、コンパイル診断1件 |
| パニック | ``- 結果：パニック `[rt.規則ID]` 行:列`` | 設定=通常、終了コード=101、パニック診断1件 |
| 警告を伴う場合（上記いずれにも付加可） | ``... / 警告：`[規則ID]` 行:列, `[規則ID]` 行:列`` | 警告数=列挙件数、各警告を過不足なく照合（順不同） |
| 設定を明示する場合 | `- 結果（通常）：...` / `- 結果（警告）：...` / `- 結果（強制）：...` | 記載された設定だけを検証対象とする |

設定とコンパイラのオプションは次のように対応する。

| 設定 | オプション |
|---|---|
| 通常 | 指定なし |
| 警告 | `--warn-unhandled-arithmetic` |
| 強制 | `--deny-unhandled-arithmetic` |

- コロンと括弧は全角（`：`・`（）`）を用いる。結果種別と終了コードまたは規則IDの間、および規則IDと `行:列` の間は半角空白1文字で区切る。警告指定は ` / 警告：` で区切り、複数の警告は `, `（カンマと半角空白1文字）で区切る。
- `- 結果：` と `- 結果（通常）：` は同じ「通常」設定として扱い、1つの例の中で同じ設定を重複させない。
- 終了コードは0から255までの先頭0なし整数とし、`0` は省略して `- 結果：正常終了` と書く（`正常終了 0` は不可）。パニック時の終了コードは常に `101` で固定する。警告の記載なしは「警告0件を要求する」意味とする。
- 行・列は1始まりの先頭0なし整数（Unicodeの文字単位）とする。パニックの規則IDは `rt.` で始まり、警告の規則IDは言語仕様の警告規則一覧にあるIDとする。同じ設定内で同じ警告（規則ID・行・列）を重複させない。
- 診断文言全体は固定せず、規則と位置を照合する。警告の出力順は問わず、過不足なく照合する。

### 実行時の出力

各ラベルの直後に空でない `text` ブロックを置く。種類ごとに1つまでとする。

| ラベル | 内容 |
|---|---|
| 標準出力 | 実行時の標準出力全文 |
| 標準エラー | 正常終了する例の標準エラー全文 |
| パニック前の標準エラー | パニック診断より前に出るログ |

記載がなければ空とする。各ブロックは末尾の改行も出力に含め、その例の実行される設定すべてに適用する。適用先のない出力ブロック（コンパイルエラーだけの例への出力指定、正常終了だけの例へのパニック前標準エラー指定など）は置けない。

パニック時は、終了コード101、標準出力、「パニック前の標準エラー」、それに続くパニック診断1件を照合する。診断の規則IDとソース位置は結果行の指定に従い、余分な出力を認めない。

### 書式エラーとして検出する条件

例の範囲内で既定値への暗黙の置き換えや読み飛ばしを行わず、上記「共通規則」「入力」「結果行」「実行時の出力」に対する次の違反をすべて書式エラーとして検出する。

- **見出し・ID**：IDの重複、不正なIDまたは空の題名。
- **メタ行のかたまり**：主根拠の欠落・重複・表記違反、補助根拠行の重複・補助根拠内の規則ID重複・主根拠と重複する補助根拠・補助根拠の表記違反、かたまり内の不正行、かたまり外に置かれたメタ行。
- **結果行**：結果行の欠落、設定の重複、未知の設定名・結果名、記号・空白区切りの違反、終了コードの `0` 明示・先頭 `0`・範囲外、診断位置の欠落・0・負値・先頭 `0`・非数字、パニック・警告の規則ID違反、空の警告一覧、同じ設定内の警告重複。
- **入力・フェンス・ラベル**：ソースの欠落・重複・空のソース、不正な16進数、閉じていないフェンス、最初の `suz` 以外の未ラベルフェンス、未知の太字ラベル（`**…：**`）、ラベルとフェンス言語の不一致、旧形式の表ラベル。
- **出力・整合性**：出力ブロックの重複・空ブロック・適用先なし、入力図の重複・`<EOF>` の欠落または途中出現・入力図とソースバイト列の不一致、主根拠・診断の規則IDが `docs/spec.md`（補助根拠は `docs/spec.md` または `docs/runtime.md`）に存在しないこと、目次表・結果別件数の表と実際の例の不一致。

## 例集の入出力だけでは検証できないこと

次のテストは例集の件数には含めない。仕様例集とRust結合テストの役割分担は[ソースの開発規約](development.md#検証する内容)に従い、追加のCソースやビルド設定、生成Cの検査が必要な保証は以下で検証する。

| 対象 | 検証テスト | 例集と分ける理由 |
|---|---|---|
| FFIのポインタ書き換え・keepによる保持 | [ffi_pointers.rs](../compiler/tests/spec_cases/ffi_pointers.rs) | 独自のCヘッダーと関数の実体が必要であり、例集はSuzソースだけを入力とする |
| C構造体・関数型のヘッダー照合、リンク失敗、extern構造体のSoA結合・生成C検査 | [ffi_structs.rs](../compiler/tests/spec_cases/ffi_structs.rs)・[ffi_link.rs](../compiler/tests/spec_cases/ffi_link.rs) | 不一致のCヘッダーやリンク対象・C関数実体を用意し、生成Cの列配置や一括ループを直接検査する必要がある |
| 作業領域の容量と計測 | [arena.rs](../compiler/tests/spec_cases/arena.rs)・[arena_report.rs](../compiler/tests/spec_cases/arena_report.rs) | 初期容量・追加容量・上限・計測の設定を切り替える必要があり、例集の結果行の設定では指定できない |
| 関数値・クロージャの環境をヒープへ確保しない保証 | [closures.rs](../compiler/tests/spec_cases/closures.rs)・[function_values.rs](../compiler/tests/spec_cases/function_values.rs) | 正常終了するだけでは無確保を確認できない。生成Cの確保呼び出しを検査する |

検証テストの実行方法と、通常検査・リリース検査の区別は[テスト基盤](../compiler/tests/README.md)を参照すること。

## 生成結果の検証

`[runtime.num-monomorphize]` の関数生成数と共有は、プログラムの出力だけでは確認できない。`compiler/src/check/tests/generic.rs` の内部表現の検査で、使用する具体型の組み合わせだけを生成することと、同じ組み合わせを共有することを確認する。
