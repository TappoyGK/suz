# Suz 仕様例集

[言語仕様](spec.md)に対する受理・拒否・実行結果の確認例。期待結果は仕様から導いたものであり、Suzコンパイラでの実行結果ではない。

## 分類とID

例は `spec-cases/` の分野別ファイルに分ける。書式と全体の件数はこのファイルで管理する。

各例には、何を確かめる例なのかを示す主根拠を1つ付け、その規則が属する仕様の章に配置する。関連するほかの規則は補助根拠として記載する。

章は仕様の順に並べ、章内は主根拠の掲載順を基本とする。同じ主根拠の例は、基本的な動作、境界条件、ほかの機能との組み合わせの順にまとめ、対応する受理例とエラー例を近くに置く。

IDは分野の接頭辞と番号で構成し、期待結果の種類を含めない。採番はリリース時に固定し、リリース済みのIDは振り直さない。リリース前は掲載順や欠番を整理して採番し直せる。その際は、文書内のファイル名や実行対象IDの参照も更新する。

## 読み方と保存方法

通常のソースブロックは、それぞれ独立した1ファイルである。IDをファイル名にし、たとえば `prog-001` は `prog-001.suz` として、コードブロックの先頭を1行目に保存する。改行はLFとする。バイト列を指定した例は、そのバイト列をそのまま保存する。

通常設定での結果を基本とし、診断設定を比較する例には別途指定する。通常終了する例の標準出力は空。標準エラーは記載したログだけで、ログがない例では空。コンパイルエラーの終了コードや診断文言、パニックの診断文言は仕様で固定されていないため、理由と位置を確認する。

バイト列の入力図では、`<CR>`は復帰文字（0d）、`<LF>`は改行文字（0a）、`<FF>`は不正なUTF-8の1バイト（ff）を表す。`<EOF>`はファイルの終端であり、文字やバイトではない。図中の改行は表示のためで、ファイルに含める改行は記号で示したものだけ。

保存用の16進数は、空白と改行を取り除き、2桁を1バイトに変換して各IDの `.suz` ファイルへ保存する。

## 期待結果の書式

### 共通規則

- 例の見出しは `### ID 題名` とし、次の同じ階層以上の見出し（`#`・`##`・`###`）または文書末尾までをその例の範囲とする。コードブロック内の見出しは区切りとして扱わない。
- IDを先頭に持つ見出し、または範囲内に「主根拠」を持つ第3階層の見出しを例として扱う。それ以外は説明用の見出しとする。
- IDは、1文字以上の英小文字、ハイフン、001から999までの3桁の番号で構成し、文書内で一意とする。
- 目次表に分野の接頭辞と件数を記載する。結果別件数も表に記載し、どちらも実際の例との一致を検証する。
- 各例に主根拠、入力、期待結果の表を1つずつ置く。主根拠は「主根拠：」に続けて規則IDをコード表記し、前後の空白と末尾の句点は判定に使わない。
- ラベルは `**期待結果：**` のように独立した行に太字で書き、次の表またはコードブロックまで空行だけを置く。
- ラベルのないコードブロックはエラーとする。日本語の説明文は機械的な判定に使わない。

各例は主根拠・補助根拠、入力、期待結果の順に記載する。入力図と保存用のバイト列も期待結果より前に置く。

### 入力

次のいずれかを指定する。

| ラベル | 形式 | 内容 |
|---|---|---|
| ソース | `suz` ブロック | 通常のソース |
| 保存用のバイト列（16進数） | `text` ブロック | 生バイトの入力 |

「入力図」は任意で1つまで置ける。直後に `text` ブロックを置き、末尾に `<EOF>` を1つ記載する。前述の記号をバイト列に復元し、入力との一致を検証する。

### 期待結果の表

列は次の順に固定する。

| 列 | 値 |
|---|---|
| 設定 | 通常・警告・強制 |
| 結果 | 正常終了・コンパイルエラー・パニック |
| 終了コード | 正常終了では0から255の整数、パニックでは101。コンパイルエラーでは `—` |
| 警告数 | 0以上の整数 |

設定とコンパイラのオプションは次のように対応する。

| 設定 | オプション |
|---|---|
| 通常 | 指定なし |
| 警告 | `--warn-unhandled-arithmetic` |
| 強制 | `--deny-unhandled-arithmetic` |

- 表は1行以上とし、同じ設定を重複させない。
- 1行を1つの検証対象とし、記載された設定だけを検証する。IDや所属する章で設定を変更しない。
- 終了コードは実行したプログラムの値を示す。コンパイルエラーでは実行しない。
- 警告数は、その設定でコンパイラが出す対象の警告件数を示す。
- 終了コードと警告数は、実際の出力との比較で検証する。

### 診断と警告の表

「コンパイル診断」「パニック診断」「警告」は、種類ごとに1つまで置ける。列を次の順に固定する。

| 列 | 値 |
|---|---|
| 設定 | 期待結果の表に記載した設定名 |
| 規則 | `[decl.shadowing]` のように、角括弧を含む規則IDをコード表記したもの |
| 行 | 1始まりの整数 |
| 列 | 1始まりの整数。Unicodeの文字単位で数える |

各表の対象と件数は次のとおりとする。

| 表 | 対象 | 件数・重複の規則 |
|---|---|---|
| コンパイル診断 | コンパイルエラーになる設定の最初のエラー | 同じ設定は1行まで |
| パニック診断 | パニックになる設定の最初に失敗する検査。規則は `rt.` で始まるID | 同じ設定は1行まで |
| 警告 | 警告対象の位置。規則は言語仕様の警告規則一覧にあるID | 1行に1件。同じ設定・規則・位置の重複は認めず、設定ごとの行数を期待結果の警告数と一致させる |

診断文言全体は固定せず、規則と位置を照合する。警告の出力順は問わず、過不足なく照合する。

診断や警告が未記載の例も抽出できる。ただし、コンパイルエラーとパニックの実行検証には、それぞれ対応する診断の記載が必要となる。警告を出す設定の実行検証には、各警告の記載が必要となる。

### 実行時の出力

各ラベルの直後に `text` ブロックを置く。種類ごとに1つまでとする。

| ラベル | 内容 |
|---|---|
| 標準出力 | 実行時の標準出力全文 |
| 標準エラー | 正常終了する例の標準エラー全文 |
| パニック前の標準エラー | パニック診断より前に出るログ |

記載がなければ空とする。各ブロックは末尾の改行も出力に含め、その例の実行される設定すべてに適用する。

パニック時は、終了コード101、標準出力、「パニック前の標準エラー」、それに続くパニック診断1件を照合する。診断の規則IDとソース位置は「パニック診断」の表に従い、余分な出力を認めない。

## 生成結果の検証

`[num.monomorphize]` の関数生成数と共有は、プログラムの出力だけでは確認できない。`compiler/src/check/tests/generic.rs` の内部表現の検査で、使用する具体型の組み合わせだけを生成することと、同じ組み合わせを共有することを確認する。
