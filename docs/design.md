# 設計記録

この文書は設計の理由と経緯を記録する。言語の規則は[言語仕様](spec.md)、実装の契約は[ランタイム仕様](runtime.md)を正本とする。記録の書き方は[仕様の執筆・レビュー基準](spec-writing.md)に従う。

## 寿命検査の前提を明記した経緯

言語仕様の`arena.soundness-premise`は、[rust-lang/rust#164250](https://github.com/rust-lang/rust/issues/164250)を受けて明記した。報告されたRustの例では、フィールドへの代入を通じて寿命の制約を満たさない値が入り、デストラクタがその値を大域の保存先へ移すことで、寿命を終えた値への参照が残った。

Suzでは、回収時に利用者のコードを実行しないこと、書き換え可能な大域の保存先を持たないこと、寿命やnull許容性の変位を認めないことを、寿命検査の前提にしている。ただし、機能が少ないために避けられている組み合わせもある。現在の制約を緩める機能は、単独の性質だけでなく、保存・返却・コールバック・回収との組み合わせを検討する必要がある。

前提そのものは[言語仕様の寿命検査の前提](spec.md#93-寿命検査の前提)、変更時の検証手順は[テスト基盤](../compiler/tests/README.md)の`test.arena-fuzz`を参照すること。生成テストとASanによる確認は検査の穴を探す手段であり、見つからなかったことだけで寿命検査全体の正しさを証明するものではない。
